Testing the box model

Run the Inspect box model bookmarklet, then click any sample. A panel should report how the box of the element you clicked is put together. Press Esc to stop.

Each sample has a small grey label above it showing the CSS used and the values you should expect in the panel. Click the coloured box, not the label.

The panel reads from the inside out: box-sizing, Content, Padding, Reserved space (scrollbar gutter), Border, Outline, Margin, then Total and Gap above. Four-sided values collapse to shorthand, so 18px 24px when the sides pair up and 1px 2px 3px 4px when they do not. The highlight is a box-shadow, not an outline.

box-sizing and content

Same declared width and height, different boxes. The panel should report the box-sizing value and the content area that results.

width: 200px; height: 100px; padding: 20px; border: 5px solid #1e3a8a
Expect: box-sizing content-box. Content 200 × 100. Padding 20px. Border 5px. Total 250 × 150. Total is larger than the declared 200 × 100, because padding and border are added outside the content

Gap above: overlap and the documented limit

A negative gap means the boxes overlap. When the overlap is larger than the neighbour's own height, the target ends up starting above the neighbour's top edge, so the tool shows no gap row. That is the documented limit, not a bug.

neighbour margin-bottom: 0; target margin-top: -20px
Click the second box. Expect: Gap above -20px. Overlap of 20px. The target starts 10px below the neighbour's top edge
