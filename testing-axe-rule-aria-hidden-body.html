Testing the axe rule aria-hidden-body

Test cases for the axe-core rule aria-hidden-body (axe-core 4.14). The rule fails when <body> has aria-hidden="true". It sets no message key and no data.

Unlike the other pages in this set, each case here is its own page, because the attribute has to go on the page's own <html> or <body> element. Open a case, then run axe over that page. Each case has its own axe report.

Things to know before reading the results:

  • Chrome ignores aria-hidden on <body> and <html>. In A1 to A3 and B1, Chrome's accessibility tree still shows all the content. NEW-47 says "some browsers" hide everything, so it's worth testing Safari and Firefox with a screen reader to see which ones do.
  • Axe treats the page as hidden even when Chrome doesn't. That's why landmark-one-main and page-has-heading-one also fail on A1 to A3, and bypass asks for review. Those extra issues would be raised alongside NEW-47.
  • This rule ignores case and spaces, so aria-hidden="TRUE" and aria-hidden="true " are caught. aria-hidden-focus doesn't, so it only fires on A1.
  • inert on the body (B2) is the real problem, and nothing names it. Chrome hides the whole page, and the only clues are the two page-level rules above.
  • Pages inside an <iframe> aren't checked. The rule only runs on the top-level page, so an embedded page with aria-hidden="true" on its body is never flagged. There's no case for this here, because the console snippet can't run axe inside frames.
