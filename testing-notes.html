All about wombats

A test page for in-context notes. Each note sits in the DOM directly after the paragraph it relates to, uses role="note", and is linked to its highlighted phrase with aria-details. Notes 2 and 4 include edit and delete buttons. To add a note, select some text and choose the Add note button that appears beside it, or use the Add note button under any paragraph. With no text selected, the note applies to the whole paragraph.

Wombats are short-legged, muscular marsupials found only in Australia. There are three living species: the common wombat, the southern hairy-nosed wombat and the northern hairy-nosed wombat. Adults usually weigh between 20 and 35 kilograms and can grow to around a metre long.

Note on 'three living species': Check the current conservation status of each species.

Wombats are well known for producing cube-shaped droppings. They leave these on rocks, logs and other raised spots to mark their territory and communicate with other wombats. The flat sides stop the droppings from rolling away.

Note on 'cube-shaped droppings': Find the research that explained how the intestine forms the cube shape.

Like all marsupials, female wombats carry their young in a pouch. A wombat's pouch has a backward-facing opening, so dirt doesn't get flung inside while the mother is digging. A joey stays in the pouch for around six months before it starts to venture out.

Note on 'backward-facing opening': Confirm whether koalas also have a backward-facing pouch.

Despite their stocky build, wombats can run surprisingly fast. Over short distances they can reach speeds of up to 40 kilometres per hour. When threatened, a wombat may dive into its burrow and block the entrance with its tough rump, which is reinforced with a thick plate of cartilage.

Note on 'up to 40 kilometres per hour': Find a reliable source for this speed figure.

Wombats face a number of threats, including habitat loss, vehicle strikes and disease. One of the most serious is sarcoptic mange, a skin disease caused by mites that can be fatal if left untreated. Wildlife carers across Australia work to treat affected wombats in the wild.

How this page works

This section outlines each feature on the page, starting with the core markup and building up to the interactive parts.

1. Core markup: mark and note

Each note has two parts: the highlighted text it refers to, and the note itself.

  • The highlighted text is wrapped in a mark element.
  • The note is an aside with role="note". The role overrides the implicit complementary role, so the page isn't flooded with landmarks.
  • The mark points to its note using aria-details. Some screen readers announce this as "has details" and offer a command to jump to the note.
  • Each note starts with a visible label, such as "Note on 'cube-shaped droppings':", so the relationship is clear even when aria-details isn't supported.
<p>
  Wombats are well known for producing
  <mark aria-details="note-2">cube-shaped droppings</mark>.
</p>

<aside role="note" id="note-2" class="note">
  <p>Note on 'cube-shaped droppings': Find the research...</p>
</aside>

2. Note placement in the DOM

  • Each note sits in the DOM directly after the paragraph it relates to, never inside the sentence. This keeps sentences intact for screen reader users, reader mode and copy and paste.
  • If a paragraph has more than one note, the notes follow each other after that paragraph.
  • On screens 860px and wider, CSS places the notes in a margin column beside their paragraph. Below 860px, notes sit directly under their paragraph.

3. Whole-paragraph notes

  • A note can apply to a whole paragraph instead of a phrase. In this case there is no mark.
  • The aria-details attribute goes on the p element instead. If a paragraph has more than one whole-paragraph note, it lists all of the IDs.
  • The visible label names the paragraph using its first few words, such as "Note on paragraph 'Like all marsupials, female…':".
<p aria-details="note-7">Like all marsupials, female wombats...</p>

<aside role="note" id="note-7" class="note">...</aside>

4. Showing and hiding notes

  • The "Show notes" button at the top of the page is a toggle button using aria-pressed. The label stays the same and the pressed state changes.
  • The label includes a count of notes, such as "Show notes (5)", so users know notes exist even when they're hidden. The count updates when notes are added or deleted.
  • Hidden notes use the hidden attribute, so they're removed for screen reader users too, not just visually.
  • When notes are hidden, aria-details is removed from the highlighted text, so screen readers don't announce details that aren't there.
  • The page remembers the user's choice using browser storage, where available.
<button type="button" aria-pressed="true">Show notes (5)</button>

5. Hover relationship

  • Hovering over highlighted text, or over a note, lights up both the text and its note.
  • On screens 860px and wider, a thin line connects the end of the highlighted text to its note. The line runs under the text rather than through it.
  • Keyboard users get the same effect when focus is on a button inside a note.
  • The line is drawn in an SVG with aria-hidden="true", as it's purely visual. The relationship is already conveyed by the visible label and aria-details.
  • In forced colours mode, the highlight and line use the system Highlight colour.

6. Adding notes

There are two ways to add a note.

  1. Select text, then use the floating button. When text is selected within a paragraph, an "Add note" button appears just below the selection. In the DOM, the button is inserted directly after the paragraph, so pressing Tab after selecting text moves focus straight to it without losing the selection. Its accessible name includes the selected text, such as "Add note on selected text 'muscular'".
  2. Use the "Add note" button under a paragraph. Every paragraph has its own button, which is always visible. If text in that paragraph is selected, the note applies to the selection. If not, the note applies to the whole paragraph. This option doesn't rely on selecting text, which many screen reader users find difficult.

After choosing either button:

  1. The new note opens in edit mode, with focus in a labelled textarea, such as "Add note on 'muscular'".
  2. Choosing Save adds the note, moves focus back to the parent paragraph and announces "Note on '…' added".
  3. Choosing Cancel, pressing Escape, or saving an empty note removes the new note and its highlight, moves focus back to the parent paragraph and announces "Note not added".

A selection must sit within a single paragraph and can't overlap an existing highlight.

7. Editing notes

  • Choosing Edit replaces the note text with a labelled textarea containing the current text, plus Save and Cancel buttons.
  • After saving or cancelling, focus returns to the note's Edit button, as the user is still working with that note.
  • Saving announces "Note on '…' saved".

8. Deleting notes

  • Choosing Delete removes the note and also removes its highlight from the text, in the same way deleting a comment works in Word.
  • Focus moves to the parent paragraph, as the button that had focus no longer exists.
  • Paragraphs aren't focusable by default. The script adds tabindex="-1" to the paragraph only at the moment of deletion, then removes it as soon as focus moves away. This avoids every paragraph being focusable all the time.
  • Deleting announces "Note on '…' deleted".

9. Unique button names

  • With many notes on a page, buttons like "Edit" and "Delete" would all sound the same in a screen reader's list of buttons.
  • Each button includes visually hidden text that names its note, such as "Delete note on 'cube-shaped droppings'".
<button type="button">
  Delete<span class="visually-hidden"> note on 'cube-shaped droppings'</span>
</button>

10. Status messages

  • Confirmation messages for adding, saving and deleting notes are sent to a visually hidden role="status" element, so screen readers announce them without moving focus.

11. Known limitations

  • Support for role="note" is inconsistent. Many screen readers don't announce the role at all, so the visible "Note on" label does most of the work.
  • Support for aria-details varies across browser and screen reader combinations.
  • Selecting text with a screen reader is possible but awkward, and may not set the starting point for the Tab key. The "Add note" button under each paragraph is the reliable option.
  • Moving from a selection to the floating button with Tab has only been confirmed in Chrome so far.
  • Notes you add are not saved. They disappear when the page is reloaded.
