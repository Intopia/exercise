aria-valid-attr-value test cases

Test cases for the axe-core rule aria-valid-attr-value (axe-core 4.14). Every example below is live in the page, so you can run the axe extension straight over it.

The expected results were checked by running axe-core 4.14.1 over this page. Look in both the axe issues list and the needs review list, because several missing ID cases only show up in needs review.

Single ID references

These attributes take exactly one ID. If the ID doesn't exist, axe fails it outright.

A1 aria-activedescendant points to a missing ID

The listbox says the active option is a1-apple, but the only option has the ID a1-banana.

Banana
<div role="listbox" tabindex="0" aria-label="Fruit" aria-activedescendant="a1-apple">
  <div role="option" id="a1-banana">Banana</div>
</div>

Expected axe result: fail

A2 aria-activedescendant points to a real ID

Control case. The ID exists, so this passes.

Carrot
<div role="listbox" tabindex="0" aria-label="Vegetables" aria-activedescendant="a2-carrot">
  <div role="option" id="a2-carrot">Carrot</div>
</div>

Expected axe result: pass (valid)

ID reference lists

These attributes can take a space separated list of IDs. Axe only needs one of the IDs to exist, and it treats some attributes more gently than others.

B1 aria-labelledby points to a missing ID

The button is labelled by b1-label, which doesn't exist.

<button type="button" aria-labelledby="b1-label">Save</button>

Expected axe result: needs review

Axe doesn't fail missing aria-labelledby IDs. It reports them as needs review.

B2 aria-labelledby with two IDs, one missing

The first ID exists, the second doesn't.

Delivery 
<span id="b2-first">Delivery</span>
<input type="text" aria-labelledby="b2-first b2-second">

Expected axe result: pass (but it's broken, check manually)

Axe passes this because at least one ID exists. The second part of the name is silently lost.

B3 aria-describedby ID has a typo

The input points to b3-hint but the hint has the ID b3-hints.

Four digits, for example 2000.

<label for="b3-input">Postcode</label>
<input type="text" id="b3-input" aria-describedby="b3-hint">
<p id="b3-hints">Four digits, for example 2000.</p>

Expected axe result: needs review

Like aria-labelledby, a missing aria-describedby ID is needs review, not a fail.

B4 aria-describedby ID uses the wrong case

The input points to b4-Hint but the hint has the ID b4-hint. IDs are case sensitive.

Include the area code.

<label for="b4-input">Phone</label>
<input type="tel" id="b4-input" aria-describedby="b4-Hint">
<p id="b4-hint">Include the area code.</p>

Expected axe result: needs review

B5 aria-describedby ID starts with a hash

Someone has written the ID like a CSS selector or link: #b5-hint.

We will never share your email.

<label for="b5-input">Email</label>
<input type="email" id="b5-input" aria-describedby="#b5-hint">
<p id="b5-hint">We will never share your email.</p>

Expected axe result: needs review

B6 aria-describedby IDs separated by a comma

The list should be space separated. With a comma, the browser looks for a single ID called b6-hint,b6-error.

At least 12 characters.

Password is too short.

<label for="b6-input">Password</label>
<input type="password" id="b6-input" aria-describedby="b6-hint,b6-error">
<p id="b6-hint">At least 12 characters.</p>
<p id="b6-error">Password is too short.</p>

Expected axe result: needs review

B7 aria-controls points to a missing ID (expanded)

The button says it's expanded and controls b7-panel, which doesn't exist.

<button type="button" aria-expanded="true" aria-controls="b7-panel">Filters</button>

Expected axe result: fail

B8 aria-controls points to a missing ID (collapsed)

Same as above, but aria-expanded="false".

<button type="button" aria-expanded="false" aria-controls="b8-panel">Sort options</button>

Expected axe result: pass (but it's broken, check manually)

Axe deliberately skips this, because many scripts only add the panel to the DOM when it opens. Open it and check again.

B9 aria-controls points to a missing ID with aria-haspopup

A menu button controlling b9-menu, which doesn't exist.

<button type="button" aria-haspopup="menu" aria-expanded="true" aria-controls="b9-menu">Account</button>

Expected axe result: needs review

With aria-haspopup set, axe assumes the popup may live elsewhere and asks you to check.

B10 aria-controls with two IDs, one missing

The first panel exists, the second doesn't.

Panel one content.
<button type="button" aria-expanded="true" aria-controls="b10-panel-1 b10-panel-2">Show all</button>
<div id="b10-panel-1">Panel one content.</div>

Expected axe result: pass (but it's broken, check manually)

One valid ID is enough for axe to pass it.

B11 aria-owns points to a missing ID

The list says it owns b11-item, which doesn't exist.

  • First item
<ul aria-owns="b11-item">
  <li>First item</li>
</ul>

Expected axe result: fail

B12 aria-owns points to a missing ID (collapsed)

A collapsed combobox that owns a listbox that doesn't exist yet.

<input type="text" role="combobox" aria-label="City" aria-expanded="false" aria-owns="b12-list">

Expected axe result: pass (but it's broken, check manually)

As with aria-controls, axe skips aria-owns when aria-expanded="false".

B13 aria-details points to a missing ID

The image points to a longer description that doesn't exist.

<img src="data:image/gif;base64,R0lGODlhAQABAAAAACw=" alt="Sales chart" aria-details="b13-details" width="40" height="40">

Expected axe result: fail

B14 aria-flowto points to a missing ID

The section says reading should continue at b14-next, which doesn't exist.

Read this first.
<div aria-flowto="b14-next">Read this first.</div>

Expected axe result: fail

aria-errormessage

Axe checks aria-errormessage separately, and only when aria-invalid is set to something other than false.

C1 aria-errormessage points to a missing ID

The field is invalid and points to c1-error, which doesn't exist.

<label for="c1-input">Name</label>
<input type="text" id="c1-input" aria-invalid="true" aria-errormessage="c1-error">

Expected axe result: needs review

C2 aria-errormessage with two IDs

aria-errormessage only allows one ID.

Enter a suburb.

Suburb not found.

<label for="c2-input">Suburb</label>
<input type="text" id="c2-input" aria-invalid="true" aria-errormessage="c2-error-1 c2-error-2">
<p id="c2-error-1" role="alert">Enter a suburb.</p>
<p id="c2-error-2" role="alert">Suburb not found.</p>

Expected axe result: fail

C3 aria-errormessage points to a hidden element

The error message exists but is hidden with the hidden attribute.

Enter a number.

<label for="c3-input">Age</label>
<input type="text" id="c3-input" aria-invalid="true" aria-errormessage="c3-error">
<p id="c3-error" role="alert" hidden>Enter a number.</p>

Expected axe result: fail

C4 aria-errormessage points to a plain paragraph

The error exists and is visible, but it isn't a live region and isn't also referenced by aria-describedby.

Choose a state.

<label for="c4-input">State</label>
<input type="text" id="c4-input" aria-invalid="true" aria-errormessage="c4-error">
<p id="c4-error">Choose a state.</p>

Expected axe result: fail

C5 Missing aria-errormessage ID, but aria-invalid="false"

The ID doesn't exist, but the field isn't invalid, so axe doesn't check it.

<label for="c5-input">Country</label>
<input type="text" id="c5-input" aria-invalid="false" aria-errormessage="c5-error">

Expected axe result: pass (but it's broken, check manually)

This will break as soon as a script flips aria-invalid to true.

C6 aria-errormessage done right

Control case. One ID, visible, and a live region.

Enter a town.

<label for="c6-input">Town</label>
<input type="text" id="c6-input" aria-invalid="true" aria-errormessage="c6-error">
<p id="c6-error" role="alert">Enter a town.</p>

Expected axe result: pass (valid)

True/false values

These attributes only accept true or false (some also accept undefined). Axe ignores case, so TRUE is fine.

D1 aria-hidden misspelled

Decorative text.

<p aria-hidden="rtue">Decorative text.</p>

Expected axe result: fail

D2 aria-required="required"

A very common mix-up with the HTML required attribute.

<label for="d2-input">Surname</label>
<input type="text" id="d2-input" aria-required="required">

Expected axe result: fail

D3 aria-disabled="disabled"

Same mix-up, this time with the HTML disabled attribute.

<button type="button" aria-disabled="disabled">Submit</button>

Expected axe result: fail

D4 aria-busy="1"

Numbers aren't allowed in place of true/false.

Loading results.
<div aria-busy="1">Loading results.</div>

Expected axe result: fail

D5 aria-modal="yes"

Are you sure?
<div role="dialog" aria-label="Confirm" aria-modal="yes">Are you sure?</div>

Expected axe result: fail

D6 aria-required="TRUE"

Control case. Uppercase is allowed.

<label for="d6-input">Given name</label>
<input type="text" id="d6-input" aria-required="TRUE">

Expected axe result: pass (valid)

Token values

These attributes accept a fixed list of keywords. Anything else is invalid.

E1 aria-checked="checked"

Allowed values are true, false and mixed.

Subscribe
<div role="checkbox" tabindex="0" aria-checked="checked">Subscribe</div>

Expected axe result: fail

E2 aria-pressed="on"

<button type="button" aria-pressed="on">Bold</button>

Expected axe result: fail

E3 aria-expanded="open"

<button type="button" aria-expanded="open">Menu</button>

Expected axe result: fail

E4 aria-selected="yes"

<div role="tablist" aria-label="Plans">
  <button type="button" role="tab" aria-selected="yes">Monthly</button>
</div>

Expected axe result: fail

E5 aria-current="yes"

Allowed values are page, step, location, date, time, true and false.

Home 
<a href="#e5" aria-current="yes">Home</a>

Expected axe result: needs review

Axe only flags invalid aria-current values as needs review, because browsers treat unknown values as true.

E6 aria-live="rude"

rude was dropped from ARIA long ago.

Status messages.
<div aria-live="rude">Status messages.</div>

Expected axe result: fail

E7 aria-autocomplete="on"

Another mix-up with the HTML attribute. Allowed values are inline, list, both and none.

<input type="text" role="combobox" aria-label="Search" aria-expanded="false" aria-autocomplete="on">

Expected axe result: fail

E8 aria-haspopup="popup"

<button type="button" aria-haspopup="popup">Options</button>

Expected axe result: fail

E9 aria-sort="asc"

It must be the full word, ascending.

Name
Alex
<table>
  <tr><th aria-sort="asc">Name</th></tr>
  <tr><td>Alex</td></tr>
</table>

Expected axe result: fail

E10 aria-invalid="error"

<label for="e10-input">Code</label>
<input type="text" id="e10-input" aria-invalid="error">

Expected axe result: fail

E11 aria-orientation="landscape"

<div role="separator" aria-orientation="landscape"></div>

Expected axe result: fail

E12 aria-relevant with one bad token

additions is fine, removed isn't (it should be removals).

Chat log.
<div aria-live="polite" aria-relevant="additions removed">Chat log.</div>

Expected axe result: fail

Number values

Some attributes need a whole number (with a minimum), others any number. Units and words aren't allowed.

F1 aria-level="two"

Contact us
<div role="heading" aria-level="two">Contact us</div>

Expected axe result: fail

F2 aria-level="0"

The lowest allowed level is 1.

About us
<div role="heading" aria-level="0">About us</div>

Expected axe result: fail

F3 aria-level="7"

Valid in ARIA, but some screen readers don't support heading levels above 6.

Fine print
<div role="heading" aria-level="7">Fine print</div>

Expected axe result: needs review

F4 aria-valuenow="fifty"

<div role="slider" tabindex="0" aria-label="Volume" aria-valuemin="0" aria-valuemax="100" aria-valuenow="fifty"></div>

Expected axe result: fail

F5 aria-valuenow="50%"

Use aria-valuetext if you want to add units.

<div role="progressbar" aria-label="Upload" aria-valuenow="50%"></div>

Expected axe result: fail

F6 aria-valuemin="0,5"

A comma as a decimal separator isn't allowed.

<div role="slider" tabindex="0" aria-label="Zoom" aria-valuemin="0,5" aria-valuemax="3" aria-valuenow="1"></div>

Expected axe result: fail

F7 aria-posinset="0"

Positions start at 1.

Small
<div role="listbox" aria-label="Sizes">
  <div role="option" aria-selected="false" aria-posinset="0" aria-setsize="3">Small</div>
</div>

Expected axe result: fail

F8 aria-colindex="1.5"

Must be a whole number.

10
<div role="grid" aria-label="Scores">
  <div role="row">
    <div role="gridcell" aria-colindex="1.5">10</div>
  </div>
</div>

Expected axe result: fail

F9 aria-setsize="-1"

Control case. -1 is allowed and means the total is unknown.

Result one
<div role="listbox" aria-label="Results">
  <div role="option" aria-selected="false" aria-posinset="1" aria-setsize="-1">Result one</div>
</div>

Expected axe result: pass (valid)

Empty values

An empty value is fine for text and ID attributes, but not for true/false, token or number attributes.

G1 aria-expanded=""

<button type="button" aria-expanded="">More</button>

Expected axe result: needs review

Axe reports empty non-text values as needs review rather than a fail.

G2 aria-hidden=""

Some text.

<p aria-hidden="">Some text.</p>

Expected axe result: needs review

G3 aria-valuenow=""

<div role="progressbar" aria-label="Download" aria-valuenow=""></div>

Expected axe result: needs review

G4 aria-labelledby=""

An empty ID list is allowed, so this rule passes it. The button still has its text as a name.

<button type="button" aria-labelledby="">Print</button>

Expected axe result: pass (valid)

Changes after interaction

Axe only sees the page as it is when you run it. Both of these pass on page load. Activate each button, then run axe again.

H1 Toggle writes aria-pressed="null"

The script reads the state from a variable that is never set, so after the first press aria-pressed becomes the text null.

On load: pass. After pressing: fail

H2 Panel is added with the wrong ID

The button starts collapsed, so axe skips the missing aria-controls target. When opened, the script adds the panel with the ID h2-pannel (typo) instead of h2-panel.

On load: pass. After opening: fail
