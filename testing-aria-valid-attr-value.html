Testing aria-valid-attr-value

Test cases for the axe-core rule aria-valid-attr-value (external site) (axe-core 4.14). Every example below is live in the page, so you can run the axe extension straight over it.

The expected results were checked by running axe-core 4.14.1 over this page. Look in both the axe issues list and the needs review list, because several missing ID cases only show up in needs review.

What this page shows

The axe-core rule aria-valid-attr-value checks that the value of an ARIA attribute is allowed. It does not check whether the attribute suits the element. This page has 55 live examples, so you can run axe over them and compare what it reports with what the examples actually do.

The examples fall into five groups. Each group tells you something different about what an automated check can and cannot find.

Fail (31 examples)

Axe reports a failure when a value is clearly invalid. There are three common causes:

  • The wrong type of value. For example, words where a number is needed (aria-level="two", aria-valuenow="50%"), "yes" or a misspelling where true or false is needed, or a keyword that does not exist (aria-live="rude", aria-sort="asc").
  • A missing ID on the attributes axe checks strictly. These are aria-activedescendant, aria-owns, aria-details, aria-flowto, and aria-controls when the control is expanded.
  • A broken aria-errormessage. It lists more than one ID, points to a hidden element, or points to a plain paragraph.

Needs review (12 examples)

Axe cannot be certain, so it asks a person to check. These results appear in the needs review list, not the issues list, so they are easy to miss. They include:

  • A missing ID on aria-labelledby or aria-describedby. The target element may be added later. Typos, the wrong case, a leading # and comma-separated IDs all end up here.
  • aria-controls together with aria-haspopup. The popup may live elsewhere in the page.
  • Values that browsers tolerate, such as an unknown aria-current value, or an aria-level above 6.
  • Empty values, such as aria-expanded="", aria-hidden="" and aria-valuenow="".

Pass, but broken (5 examples)

These examples have real problems that axe passes. They show why a clean result does not mean the markup is correct:

  • A list where one ID is valid. Axe only needs one of the IDs to exist, so the missing part of a name or a control is silently lost.
  • Collapsed controls. Axe skips a missing aria-controls or aria-owns target when aria-expanded="false", because many scripts only add the panel when it opens.
  • A problem waiting to happen. A missing aria-errormessage ID is ignored while aria-invalid="false", but it breaks as soon as a script marks the field invalid.

Pass, valid control cases (5 examples)

These are correct examples that should pass. They confirm that the rule does not flag everything. They include an ID that exists, aria-required="TRUE" (the case of a true or false value does not matter), aria-setsize="-1" (allowed, and means the total is unknown), an empty aria-labelledby (allowed), and a correctly built aria-errormessage.

Changes after interaction (2 examples)

Both examples pass when the page loads and fail after you use them. One toggle button writes aria-pressed="null". One disclosure button builds its panel with a typo in the ID. Axe only tests the page as it is at the moment you run it, so open, press and toggle things, then run axe again.

The takeaway

Axe is good at catching clearly invalid values. It is honest about the cases it cannot judge, and it cannot see problems that only exist in a collapsed, partial or later state. Automated results are a starting point, and manual testing is still needed.

Single ID references

These attributes take exactly one ID. If the ID doesn't exist, axe fails it outright.

Example A1: aria-activedescendant points to a missing ID

The listbox says the active option is a1-apple, but the only option has the ID a1-banana.

Expected axe result: fail.

Banana
HTML markup 
<div role="listbox" tabindex="0" aria-label="Fruit" aria-activedescendant="a1-apple">
  <div role="option" id="a1-banana">Banana</div>
</div>

Example A2: aria-activedescendant points to a real ID

Control case. The ID exists, so this passes.

Expected axe result: pass (valid).

Carrot
HTML markup 
<div role="listbox" tabindex="0" aria-label="Vegetables" aria-activedescendant="a2-carrot">
  <div role="option" id="a2-carrot">Carrot</div>
</div>

ID reference lists

These attributes can take a space separated list of IDs. Axe only needs one of the IDs to exist, and it treats some attributes more gently than others.

Changes after interaction

Axe only sees the page as it is when you run it. Both of these pass on page load. Activate each button, then run axe again.

Example H1: Toggle writes aria-pressed="null"

The script reads the state from a variable that is never set, so after the first press aria-pressed becomes the text null.

Expected axe result: pass on load, fail after pressing.

HTML markup 
<button type="button" id="h1-button" aria-pressed="false">Italic</button>
JavaScript 
var pressedState;
document.getElementById('h1-button').addEventListener('click', function () {
  var current = this.getAttribute('aria-pressed') === 'true';
  pressedState = current ? 'false' : null; // bug: should be 'true'
  this.setAttribute('aria-pressed', String(pressedState));
});

Example H2: Panel is added with the wrong ID

The button starts collapsed, so axe skips the missing aria-controls target. When opened, the script adds the panel with the ID h2-pannel (typo) instead of h2-panel.

Expected axe result: pass on load, fail after opening.

HTML markup 
<button type="button" id="h2-button" aria-expanded="false" aria-controls="h2-panel">Shipping details</button>
<div id="h2-container"></div>
JavaScript 
document.getElementById('h2-button').addEventListener('click', function () {
  var container = document.getElementById('h2-container');
  var isOpen = this.getAttribute('aria-expanded') === 'true';
  if (isOpen) {
    this.setAttribute('aria-expanded', 'false');
    container.innerHTML = '';
  } else {
    this.setAttribute('aria-expanded', 'true');
    container.innerHTML = '<div id="h2-pannel"><p>Standard shipping takes 3 to 5 days.</p></div>';
  }
});
