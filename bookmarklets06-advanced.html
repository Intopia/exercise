Article 6: Additional accessibility bookmarklets

This article introduces six bookmarklets that help you inspect accessible forms. Together, they make it easier to review labels, grouped controls, validation and autocomplete without inspecting the page's source code.

Bookmarklets are small browser tools that inspect or highlight different aspects of a web page. If you haven't used bookmarklets before, read our introduction first.

All bookmarklets featured in this article are available on the Accessibility testing bookmarklets page.

22. Highlight aria-expanded

What it does

Highlights elements that use the aria-expanded attribute. It distinguishes between expanded and collapsed states, making it easy to inspect controls that show or hide content.

It also flags invalid aria-expanded values.

When to use it

Use this bookmarklet when you want to:

  • identify elements that use aria-expanded
  • inspect the current expanded or collapsed state of interactive controls
  • check that aria-expanded has been applied correctly
  • identify invalid aria-expanded values

How to use it

  1. Drag a bookmarklet to your browser's Bookmarks Bar.
  2. Open the page you want to inspect.
  3. Click the Highlight aria-expanded bookmarklet.
  4. Scroll through the page to review the highlighted elements.
  5. If you expand or collapse a control, run the bookmarklet again to refresh the displayed values.
  6. Press Esc to remove the overlay.

What to look for

When reviewing the page, check for:

  • Elements with aria-expanded="true", indicating that the associated content is currently expanded.
  • Elements with aria-expanded="false", indicating that the associated content is currently collapsed.
  • Controls that update their aria-expanded value when activated.
  • Invalid aria-expanded values, which are not recognised by the ARIA specification.

Things to be aware of

This bookmarklet shows the current value of the aria-expanded attribute, but it can't determine whether the control behaves correctly or whether the expanded content is accessible.

If you interact with a control after running the bookmarklet, run it again to refresh the displayed values.

Remember

Use aria-expanded to communicate whether expandable content is currently expanded or collapsed. Whenever the state changes, the value of aria-expanded should be updated to reflect the current state.

23. Highlight aria-checked

What it does

Highlights elements that use the aria-checked attribute. It distinguishes between the supported checked states:

  • true
  • false
  • mixed

It also flags invalid aria-checked values.

This makes it easy to inspect the current state of checkboxes, switches and other checkable widgets.

When to use it

Use this bookmarklet when you want to:

  • identify elements that use aria-checked
  • inspect the current checked state of interactive widgets
  • distinguish between checked, unchecked and mixed states
  • identify invalid aria-checked values

How to use it

  1. Drag a bookmarklet to your browser's Bookmarks Bar.
  2. Open the page you want to inspect.
  3. Click the Highlight aria-checked bookmarklet.
  4. Scroll through the page to review the highlighted elements.
  5. If you interact with a widget, run the bookmarklet again to refresh the displayed values.
  6. Press Esc to remove the overlay.

What to look for

When reviewing the page, check for:

  • Elements with aria-checked="true", indicating they are currently checked.
  • Elements with aria-checked="false", indicating they are currently unchecked.
  • Elements with aria-checked="mixed", indicating a partially selected or indeterminate state.
  • Invalid aria-checked values, which are not recognised by the ARIA specification.
  • Widgets that update their aria-checked value when their state changes.

Things to be aware of

This bookmarklet shows the current value of the aria-checked attribute, but it can't determine whether the widget behaves correctly or whether the chosen state is appropriate.

If you interact with a widget after running the bookmarklet, run it again to refresh the displayed values.

Remember

Use aria-checked to communicate the current state of checkable widgets. Whenever the state changes, the value of aria-checked should be updated so that assistive technologies receive accurate information.

24. Highlight Shadow DOM

What it does

Highlights elements that use open Shadow DOM and identifies custom elements that may use Shadow DOM but cannot be confirmed.

It distinguishes between:

  • Open Shadow DOM hosts, where the shadow tree can be inspected.
  • Custom elements, which may or may not use Shadow DOM.

A fixed summary banner at the bottom of the page displays the total number of open Shadow DOM hosts and custom elements found.

When to use it

Use this bookmarklet when you want to:

  • identify components that use Shadow DOM
  • inspect pages built with Web Components
  • distinguish between open Shadow DOM and custom elements
  • understand why other bookmarklets may not detect some page content

How to use it

  1. Drag a bookmarklet to your browser's Bookmarks Bar.
  2. Open the page you want to inspect.
  3. Click the Highlight Shadow DOM bookmarklet.
  4. Scroll through the page to review the highlighted components.
  5. Check the summary banner at the bottom of the page for the total counts.
  6. Press Esc to remove the overlay.

What to look for

When reviewing the page, check for:

  • Open Shadow DOM hosts, which can be inspected by bookmarklets and browser developer tools.
  • Custom elements, which may or may not contain a Shadow DOM.
  • Pages that make extensive use of Web Components, as these may affect how other accessibility testing tools behave.
  • The summary banner, which provides a quick overview of the number of components identified.

Things to be aware of

This bookmarklet can only identify open Shadow DOM. It can't detect or inspect closed Shadow DOM, as browsers intentionally prevent scripts from accessing it.

Similarly, finding a custom element doesn't necessarily mean it contains a Shadow DOM. Some custom elements don't use Shadow DOM at all, while others use a closed Shadow DOM that cannot be inspected.

Remember

Shadow DOM changes how parts of a page are exposed to browser tools. Understanding where Shadow DOM is used can help explain why some accessibility testing tools and bookmarklets can't inspect every part of a page.
