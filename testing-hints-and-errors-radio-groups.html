Testing hints and errors on radio groups

Hints and error messages for a group of radios need to be programmatically associated with the group, not just placed near it. Hints and errors use the same method, so they are tested together. Every example is pre-set in the markup, so no JavaScript is needed.

Simplest approach: link the hint or error to the group with aria-describedby. See Recommended practice.

Every example has a coloured box showing how to read it:

Poor practice: allowed, but not recommended.

Acceptable: allowed, and does part or all of the job. The box says what it does and does not give you.

Control: a baseline.

1. Controls

Baselines with no hint or error shown.

Example 1.1: fieldset

Control: A group with no hint or error shown.

Which is your favourite pet?
HTML markup 
<fieldset>
  <legend>Which is your favourite pet?</legend>
  <div>
    <input type="radio" id="r1-dog" name="r1" value="dog">
    <label for="r1-dog">Dog</label>
  </div>
  <div>
    <input type="radio" id="r1-cat" name="r1" value="cat">
    <label for="r1-cat">Cat</label>
  </div>
  <div>
    <input type="radio" id="r1-rabbit" name="r1" value="rabbit">
    <label for="r1-rabbit">Rabbit</label>
  </div>
</fieldset>

2. Text with no association

The hint or error is visible, but nothing links it to the group.

None of these options is good practice.

Example 2.1: Hint, not linked

Poor practice: The hint is in a paragraph inside the group. Nothing associates it with the group, so assistive technology users may not hear it.

Which is your favourite pet?

Choose one pet.

<fieldset>
  <legend>Which is your favourite pet?</legend>
  <p>Choose one pet.</p>
  <div>

3. Error as text in the group's name

The error message is written into the group's name: the legend, or the labelling element.

None of these options is good practice.

Example 3.1: fieldset

Poor practice: The error is part of the group's accessible name, so it is announced when users enter the group. But it makes the name longer and changes it whenever there is an error. Prefer aria-describedby.

Which is your favourite pet? Error: Choose one pet.
HTML markup 
<fieldset>
  <legend>Which is your favourite pet? <span class="error">Error: Choose one pet.</span></legend>

    <input type="radio" id="r6-dog" name="r6" value="dog">

4. Hint linked to the group

The hint is linked to the group with aria-describedby.

Example 4.1: fieldset

Acceptable: The hint is associated with the group with aria-describedby, so assistive technology can announce it as the group's description.

Which is your favourite pet?

Choose one pet.

HTML markup

7. aria-describedby on the radios

The hint or error is linked to the radios themselves.

None of these options is good practice.

Example 7.1: aria-describedby on each radio

Poor practice: The error is repeated on every radio, and it is not associated with the group itself.

Which is your favourite pet?

Error: Choose one pet.

HTML markup 
<fieldset>
  <legend>Which is your favourite pet?</legend>
  <p class="error" id="r18-error">Error: Choose one pet.</p>
  <div>
    <input type="radio" id="r18-dog" name="r18" value="dog" aria-describedby="r18-error">
    <label for="r18-dog">Dog</label>
  </div>
  <div>
    <input type="radio" id="r18-cat" name="r18" value="cat" aria-describedby="r18-error">
    <label for="r18-cat">Cat</label>
  </div>
  <div>
    <input type="radio" id="r18-rabbit" name="r18" value="rabbit" aria-describedby="r18-error">
    <label for="r18-rabbit">Rabbit</label>
  </div>
</fieldset>
