Testing the document title

These tests check whether each page has a document title that VoiceOver can announce, and whether that title helps users know where they are.

VoiceOver announces the document title as part of the window summary. Press VO+F2 to hear it. On most laptops, press VO+Fn+F2 .

1

Test 1: Does VoiceOver announce a document title?

How to check: Press VO+F2 and listen for the page title in the window summary.

Related WCAG criteria:

  • 2.4.2 Page Titled (Level A)
2

Test 2: Does the document title describe the topic or purpose of the page?

How to check: Press VO+F2 and compare what you hear with the main content of the page.

Related WCAG criteria:

  • 2.4.2 Page Titled (Level A)
3

Test 3: Does the document title distinguish this page from other pages on the site?

How to check: Visit two or three different pages, press VO+F2 on each page, and compare the titles.

Related WCAG criteria:

  • 2.4.2 Page Titled (Level A)
4

Test 4: When the main content changes without a full page load, does the document title update?

How to check: Trigger a change that displays a different page or view (for example, navigate within a single-page application), then press VO+F2 .

Related WCAG criteria:

  • 2.4.2 Page Titled (Level A)

Testing headings

These tests check whether VoiceOver announces the headings on a page, and whether those headings provide a useful outline of the content.

Headings are not in the Tab order, so these tests use single-key Quick Nav. Press VO+Q to turn it on. If you prefer, you can use VO+Command+H instead of H.

1

Test 1: Does the page contain at least one heading?

How to check: Press H to navigate through headings. Check that VoiceOver identifies at least one heading on the page. If the page has no headings, VoiceOver will not move to a heading.

Related WCAG criteria:

  • 1.3.1 Info and Relationships (Level A)
2

Test 2: Does VoiceOver announce every visible heading as a heading?

How to check: Press H to move through the headings and compare what VoiceOver announces with the headings you can see on screen.

Related WCAG criteria:

  • 1.3.1 Info and Relationships (Level A)
3

Test 3: Is everything VoiceOver announces as a heading actually a heading?

How to check: Press H to move through the headings and check that each one identifies a section or subsection of content.

Related WCAG criteria:

  • 1.3.1 Info and Relationships (Level A)
4

Test 4: Does every heading contain text?

How to check: Press H to move through the headings and listen for any that announce only a heading level, such as "heading level 2", without a name.

Related WCAG criteria:

  • 1.3.1 Info and Relationships (Level A)
5

Test 5: Do the heading levels reflect the structure of the page?

How to check: Open the rotor ( VO+U ), use the Left Arrow or Right Arrow key to move to the Headings list, and check that the heading levels reflect the relationships between sections and subsections.

Related WCAG criteria:

  • 1.3.1 Info and Relationships (Level A)
6

Test 6: Does each heading describe the content that follows it?

How to check: Open the rotor ( VO+U ), move to the Headings list, and review whether the headings provide a useful outline of the page. Where necessary, press Enter to move to a heading, then press VO+Right Arrow to read the content that follows.

Related WCAG criteria:

  • 2.4.6 Headings and Labels (Level AA)

Testing links

These tests check whether VoiceOver announces each link with a name that helps users understand its purpose.

These tests use the Tab key. Tab also stops on buttons and form fields, so focus on the links as you go. If you prefer, you can press L with single-key Quick Nav on ( VO+Q ) to move through links only.

If you are testing in Safari, make sure "Press Tab to highlight each item on a webpage" is turned on in Safari's Advanced settings, or Tab will skip links.

1

Test 1: Does VoiceOver announce every visible link as a link?

How to check: Press Tab to move through the links and compare what VoiceOver announces with the links you can see on screen.

Related WCAG criteria:

  • 4.1.2 Name, Role, Value (Level A)
2

Test 2: Does VoiceOver announce a name for every link?

How to check: Press Tab to move through the links and listen for any announced without a name, such as just "link", or announced as a file name or web address.

Related WCAG criteria:

  • 4.1.2 Name, Role, Value (Level A)
  • 2.4.4 Link Purpose (In Context) (Level A)
3

Test 3: Does VoiceOver announce the visible link text as part of each link's name?

How to check: Press Tab to move through the links and compare the announced names with the visible link text. The visible text should be included, although additional words may be announced.

Related WCAG criteria:

  • 2.5.3 Label in Name (Level A)
4

Test 4: Can the purpose of each link be determined from its name or surrounding content?

How to check: Press Tab to move through the links. Where a link is unclear on its own (such as "Read more"), press VO+Left Arrow and VO+Right Arrow to read the surrounding sentence, paragraph, list item or table cell.

Related WCAG criteria:

  • 2.4.4 Link Purpose (In Context) (Level A)
5

Test 5: Are users informed when links have unusual behaviour? Best practice

How to check: Press Tab to move through the links and listen for information about actions such as downloading a file, opening a new window or starting an email.

Related WCAG criteria: None (best practice)

Testing landmarks

These tests check whether the page has landmarks that help VoiceOver users move between its main sections. All landmark tests are best practice rather than WCAG requirements.

Landmarks are not in the Tab order, so these tests use the rotor. Press VO+U to open the rotor, then use the Left Arrow or Right Arrow key to move to the Landmarks list.

1

Test 1: Does the page have landmarks that identify its main sections? Best practice

How to check: Open the rotor ( VO+U ) and move to the Landmarks list. Listen for landmarks such as banner, navigation, main and content information (footer).

Related WCAG criteria: None (best practice)

2

Test 2: When multiple landmarks of the same type are present, can they be distinguished by their names? Best practice

How to check: Open the rotor ( VO+U ) and move to the Landmarks list. Where multiple landmarks of the same type are present, check that VoiceOver announces names that distinguish them, such as "Primary navigation" and "Footer navigation".

Related WCAG criteria: None (best practice)

3

Test 3: Does the page have one main landmark? Best practice

How to check: Open the rotor ( VO+U ), move to the Landmarks list, and check that there is exactly one main landmark.

Related WCAG criteria: None (best practice)

Testing images

These tests check whether VoiceOver provides users with the information and functionality conveyed by images. Before you start, decide which images on the page are informative, functional or complex.

Images are not in the Tab order, so most of these tests use VO+Command+G to move to the next image. Press VO+Command+Shift+G to move to the previous image.

VoiceOver has a "Navigate images" setting in the Web category of VoiceOver Utility. If VoiceOver seems to skip images, check this setting.

1

Test 1: Does VoiceOver announce every image without reading a file name or path?

How to check: Press VO+Command+G to move through the images and listen for any announced as a file name or path, or as just "image".

Related WCAG criteria:

  • 1.1.1 Non-text Content (Level A)
2

Test 2: Does VoiceOver announce every informative image?

How to check: Press VO+Command+G to move through the images and compare what VoiceOver announces with the images you can see on screen. Any informative image VoiceOver skips is a fail.

Related WCAG criteria:

  • 1.1.1 Non-text Content (Level A)
3

Test 3: Does VoiceOver announce a text alternative that conveys the meaning of each informative image?

How to check: Press VO+Command+G to move through the images. For each one, compare what VoiceOver announces with what the image shows.

Related WCAG criteria:

  • 1.1.1 Non-text Content (Level A)
4

Test 4: Does VoiceOver announce a name for each image link or button that conveys its purpose?

How to check: Press Tab to move through links and buttons. For any that contain an image, check that what VoiceOver announces describes what the link or button does, not what the image looks like.

Related WCAG criteria:

  • 1.1.1 Non-text Content (Level A)
  • 4.1.2 Name, Role, Value (Level A)
5

Test 5: Does each complex image have a longer description available?

How to check: Press VO+Command+G to move to the complex image, such as a chart or diagram, then press VO+Left Arrow and VO+Right Arrow to read the content around it. Check for a description on the page, or a link to one.

Related WCAG criteria:

  • 1.1.1 Non-text Content (Level A)

Testing lists

These tests check whether VoiceOver announces lists as lists, along with the correct number of items.

Lists are not in the Tab order, so these tests use VO+Command+X to move to the next list. Press VO+Command+Shift+X to move to the previous list.

1

Test 1: Does VoiceOver announce every visible list as a list?

How to check: Press VO+Command+X to move through the lists and compare what VoiceOver announces with the lists you can see on screen.

Related WCAG criteria:

  • 1.3.1 Info and Relationships (Level A)
2

Test 2: Does VoiceOver announce the correct number of items for each list?

How to check: Press VO+Command+X to move to each list and listen for the item count, such as "list, 5 items". Compare it with the number of items you can see on screen.

Related WCAG criteria:

  • 1.3.1 Info and Relationships (Level A)

Testing tables

These tests check whether VoiceOver announces data tables, their size, and their headers as you move through them. They apply to data tables only, not tables used for layout.

Tables are not in the Tab order, so these tests use VO+Command+T to move to the next table. Press VO+Command+Shift+T to move to the previous table.

To move between cells, use VO+Arrow keys. If this doesn't work, you may need to interact with the table first by pressing VO+Shift+Down Arrow . Press VO+Shift+Up Arrow to stop interacting.

1

Test 1: Does VoiceOver announce every visible data table as a table?

How to check: Press VO+Command+T to move through the tables and compare what VoiceOver announces with the data tables you can see on screen.

Related WCAG criteria:

  • 1.3.1 Info and Relationships (Level A)
2

Test 2: Does VoiceOver announce the correct number of rows and columns for each table?

How to check: Press VO+Command+T to move to each table and listen for the size, such as "table, 5 rows, 4 columns". Compare it with the rows and columns you can see on screen.

Related WCAG criteria:

  • 1.3.1 Info and Relationships (Level A)
3

Test 3: Does VoiceOver announce the column header when moving across a row?

How to check: Move into a table, then press VO+Right Arrow to move across a row. As you move into each new column, VoiceOver should announce that column's header along with the cell content.

Related WCAG criteria:

  • 1.3.1 Info and Relationships (Level A)
4

Test 4: Does VoiceOver announce the row header when moving down a column?

How to check: Move into a table, then press VO+Down Arrow to move down a column. As you move into each new row, VoiceOver should announce that row's header along with the cell content. This only applies to tables with row headers.

Related WCAG criteria:

  • 1.3.1 Info and Relationships (Level A)
5

Test 5: Does VoiceOver announce a name for each table? Best practice

How to check: Press VO+Command+T to move to each table and listen for a name that describes the table's content, announced along with "table".

Related WCAG criteria: None (best practice)

Testing labels for form fields

These tests check whether VoiceOver announces each form field with a name that matches its visible label and describes what users need to enter or select.

These tests use the Tab key. Tab also stops on links and buttons, so focus on the form fields as you go.

1

Test 1: Does VoiceOver announce every visible form field as a form field?

How to check: Press Tab to move through the form fields and compare what VoiceOver announces with the fields you can see on screen. Listen for the field type, such as "edit text", "checkbox" or "pop-up button", and check it matches what you see.

Related WCAG criteria:

  • 4.1.2 Name, Role, Value (Level A)
2

Test 2: Does VoiceOver announce a name for every form field?

How to check: Press Tab to move through the form fields and listen for any announced without a name, such as just "edit text" or "pop-up button".

Related WCAG criteria:

  • 4.1.2 Name, Role, Value (Level A)
  • 1.3.1 Info and Relationships (Level A)
3

Test 3: Does VoiceOver announce the visible label as part of each form field's name?

How to check: Press Tab to move through the form fields and compare the announced names with the visible labels. The visible label should be included, although additional words may be announced.

Related WCAG criteria:

  • 2.5.3 Label in Name (Level A)
4

Test 4: Does each form field's name describe the information required?

How to check: Press Tab to move through the form fields and check that each name makes clear what to enter or select, without needing to see the screen.

Related WCAG criteria:

  • 2.4.6 Headings and Labels (Level AA)

Testing form field instructions

These tests check whether VoiceOver announces a field's instructions, such as a date format or password rules, when you move to that field.

VoiceOver often reads instructions after a short pause . After you press Tab , wait a moment before moving on, so you don't miss them.

1

Test 1: Does VoiceOver announce the instructions for each form field when moving to that field?

How to check: Press Tab to move through the form fields. For each field with visible instructions, such as a date format or password rules, listen for the instructions in the announcement.

Related WCAG criteria:

  • 3.3.2 Labels or Instructions (Level A)
  • 1.3.1 Info and Relationships (Level A)
2

Test 2: Does VoiceOver announce each set of instructions with the correct form field?

How to check: Press Tab to move through the form fields and check that the instructions VoiceOver announces match the instructions shown next to that field on screen.

Related WCAG criteria:

  • 1.3.1 Info and Relationships (Level A)
3

Test 3: Does VoiceOver announce the instructions in full?

How to check: Press Tab to move through the form fields and compare the announced instructions with the visible instructions. Listen for any that are cut short or missing part of the text.

Related WCAG criteria:

  • 3.3.2 Labels or Instructions (Level A)

Testing overall labels for radio and checkbox groups

These tests check whether VoiceOver announces the question or label for each group of radio buttons or checkboxes, not just the individual options.

These tests use the Tab key. Remember that Tab moves into a radio group once. Use the arrow keys to move between the options inside it.

1

Test 1: Does VoiceOver announce every visible radio and checkbox group as a group?

How to check: Press Tab to move into the first option of each group. Listen for "group" or similar, and compare with the groups you can see on screen.

Related WCAG criteria:

  • 1.3.1 Info and Relationships (Level A)
2

Test 2: Does VoiceOver announce a name for every radio and checkbox group?

How to check: Press Tab to move into each group and listen for a group name along with the first option, such as "Delivery method, group".

Related WCAG criteria:

  • 1.3.1 Info and Relationships (Level A)
3

Test 3: Does VoiceOver announce the visible group label as part of each group's name?

How to check: Compare the announced group name with the question or label shown above the group on screen.

Related WCAG criteria:

  • 1.3.1 Info and Relationships (Level A)
4

Test 4: Does each group's name describe the question being asked?

How to check: Listen to the group name on its own and check that it makes clear what you're choosing, such as "Delivery method" rather than "Options".

Related WCAG criteria:

  • 2.4.6 Headings and Labels (Level AA)

Test 2: Does VoiceOver announce each set of instructions with the correct group?

How to check: Press Tab to move into each group and check that the instructions VoiceOver announces match the instructions shown with that group on screen.

Related WCAG criteria:

  • 1.3.1 Info and Relationships (Level A)
3

Test 3: Does VoiceOver announce the group instructions in full?

Testing required fields

These tests check whether VoiceOver users can identify which form fields are required, and whether optional fields are incorrectly announced as required.

These tests use the Tab key. Tab also stops on links and buttons, so focus on the form fields as you go.

1

Test 1: Can VoiceOver users identify every required form field?

How to check: Press Tab to move through the form fields and listen for "required" in each field's announcement. If it's missing, press VO+Left Arrow and VO+Right Arrow to read the content above the form for a statement such as "All fields are required".

Related WCAG criteria:

  • 3.3.2 Labels or Instructions (Level A)
  • 1.3.1 Info and Relationships (Level A)
2

Test 2: Is every form field VoiceOver announces as required actually required?

How to check: Press Tab to move through the form fields. For each field VoiceOver announces as "required", check that it's shown as required on screen.

Related WCAG criteria:

  • 1.3.1 Info and Relationships (Level A)
3

Test 3: Does VoiceOver announce "required" as a state for every required form field? Best practice

How to check: Press Tab to move through the form fields and listen for "required" announced separately from the field's name. If "required" is only read as part of the name, such as "First name required", it's part of the label text rather than a state.

Related WCAG criteria: None (best practice)

Testing form field errors

These tests check whether VoiceOver announces each error message with its field, and whether the message helps users fix the problem.

VoiceOver often reads error messages after a short pause . After you press Tab , wait a moment before moving on, so you don't miss them.

1

Test 1: Does VoiceOver announce the error message for each form field with an error, when moving to that field?

How to check: Submit the form with errors, then press Tab to move through the form fields. For each field showing an error on screen, listen for the error message in the announcement.

Related WCAG criteria:

  • 3.3.1 Error Identification (Level A)
2

Test 2: Does VoiceOver announce each error message with the correct form field?

How to check: Press Tab to move through the form fields and check that the error VoiceOver announces matches the error shown next to that field on screen.

Related WCAG criteria:

  • 3.3.1 Error Identification (Level A)
3

Test 3: Does VoiceOver announce each error message in full?

How to check: Press Tab to move through the form fields and compare the announced error with the visible error. Listen for any that are cut short or missing part of the text.

Related WCAG criteria:

  • 3.3.1 Error Identification (Level A)
4

Test 4: Does each error message describe how to fix the problem?

How to check: Press Tab to move through the form fields and listen to each error. Check that it tells you what to do, such as " Enter a date in DD/MM/YYYY format", rather than just "Invalid date".

Related WCAG criteria:

  • 3.3.3 Error Suggestion (Level AA)
5

Test 5: Does VoiceOver stop announcing the error once the field has been corrected?

How to check: Correct the field, resubmit the form or move away from the field, then Tab back to it. Check that VoiceOver no longer announces the error.

Related WCAG criteria:

  • 3.3.1 Error Identification (Level A)
6

Test 6: Does VoiceOver announce "invalid data" for each form field with an error? Best practice

How to check: Press Tab to move through the form fields with errors and listen for "invalid data" in the announcement.

Related WCAG criteria: None (best practice)

7

Test 7: Does VoiceOver avoid announcing errors before the user has finished with the field? Best practice

How to check: Reload the form, then move to a form field for the first time and listen for any error message or "invalid data". Then type part of a value, such as the first few letters of an email address, and listen for any error announced while you're still typing. Errors announced after leaving the field or after submitting the form are fine.

Related WCAG criteria: None (best practice)

Testing on-submit errors

These tests check how VoiceOver handles errors when a form is submitted, including where focus moves and how users can navigate to fields with errors. Tests 1, 2 and 4 are based on Intopia's recommendations rather than WCAG requirements.

1

Test 1: For forms with two fields or fewer, does focus move to the first field with an error when the form is submitted?

How to check: Submit the form with errors. Listen for VoiceOver to announce the first field with an error, including its name and error message.

Related WCAG criteria:

  • None (Intopia recommendation)
2

Test 2: For forms with more than two fields, does focus move to an error summary above the form when the form is submitted?

How to check: Submit the form with errors. Listen for VoiceOver to announce the error summary, rather than staying silent or announcing the submit button again.

Related WCAG criteria:

  • None (Intopia recommendation)
3

Test 3: Does the error summary list every error in the form?

How to check: After submitting, press VO+Right Arrow to read through the error summary. Compare the errors announced with the errors shown next to the fields on screen.

Related WCAG criteria:

  • 3.3.1 Error Identification (Level A)
4

Test 4: Does each error in the summary take you to the field it describes?

How to check: Press Tab to move to each error link in the summary and press Enter to activate it. Listen for VoiceOver to announce the matching form field.

Related WCAG criteria:

  • None (Intopia recommendation)
