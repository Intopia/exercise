Testing the axe rule aria-required-children

Test cases for the axe-core rule aria-required-children (axe-core 4.14). Some roles describe a group of items, such as a list, a menu or a set of tabs. The rule checks two things about the elements inside them:

  • Required children: the group contains at least one element with a role it needs, such as listitem in a list.
  • Children that aren't allowed: the group doesn't contain elements with other roles, or focusable elements with no role.

The rule only looks at elements with an explicit role attribute. A native <ul> is checked by the separate list rule instead.

These are the roles axe checks, and the children it accepts:

Children that aren't allowed

These fail with "Element has children which are not allowed". Each has a message key.

B1 Tablist with focusable div tabs

Once the divs have tabindex, axe treats them as interactive elements with no role, which aren't allowed in a tablist.

Profile
Settings
<div role="tablist" aria-label="Account">
  <div tabindex="0">Profile</div>
  <div tabindex="-1">Settings</div>
</div>

Expected result: fail

Template routing: Message key: unallowed. Routes to: NEW-49.

B2 Tablist with button tabs

A common pattern. The buttons have the role button, not tab.

<div role="tablist" aria-label="Plans">
  <button type="button">Monthly</button>
  <button type="button">Yearly</button>
</div>

Expected result: fail

Template routing: Message key: unallowed. Routes to: NEW-49.

B3 Heading inside a list

A heading has its own role, so it isn't allowed between list items.

Our team

Alex
Sam
<div role="list">
  <h4>Our team</h4>
  <div role="listitem">Alex</div>
  <div role="listitem">Sam</div>
</div>

Expected result: fail

Template routing: Message key: unallowed. Routes to: NEW-49.

B4 Menu item with a global attribute but no role

A global ARIA attribute makes axe treat the div as meaningful, so it isn't ignored.

Paste

Pastes the last item you copied.

<div role="menu" aria-label="Clipboard">
  <div aria-describedby="b4-hint">Paste</div>
</div>
<p id="b4-hint">Pastes the last item you copied.</p>

Expected result: fail

Template routing: Message key: unallowed. Routes to: NEW-49.

B5 A ul between a listbox and its options

The <ul> has the role list, which isn't allowed in a listbox.

  • Red
<div role="listbox" aria-label="Colour">
  <ul>
    <li role="option" aria-selected="true">Red</li>
  </ul>
</div>

Expected result: fail

This one element raises three results: this rule, aria-required-parent (the option isn't directly in the listbox) and list (the <li> no longer counts as a list item).

Template routing: Message key: unallowed. Routes to: NEW-49, plus NEW-46 for the option.

B6 Focusable wrapper around a list item

  </div>
</div>

Not checked by this rule

E1 A native ul with div children

No role attribute, so this rule doesn't look at it. The list rule catches it instead.

    First
<ul>
  <div>First</div>
</ul>

Expected result: flagged by list instead

Template routing: Not an ARIA rule, so outside this template set.

E2 Empty radiogroup

ARIA 1.2 expects a radiogroup to contain radios, but axe doesn't check radiogroup at all. Nothing flags it.

<div role="radiogroup" aria-label="Size"></div>

Expected result: passes, but it's broken (check manually)

Template routing: No result, so nothing to route.

Changes after interaction

Axe only sees the page as it is when you run it. These pass on page load. Activate each button, then run axe again.

F1 Tabs load, but they're plain divs

On load the tablist is empty and aria-busy="true", so it passes. The button adds the tabs and sets aria-busy="false", but the tabs have no role.

<button type="button" id="f1-load">Load tabs</button>
<div role="tablist" aria-label="Topics" id="f1-tablist" aria-busy="true"></div>

On load: pass. After loading: fail

After loading, the message key is none, so it routes to NEW-45 once the mapping is fixed.

F2 Menu that's hidden until opened

Axe doesn't test hidden content. Open the menu and its focusable div items are found.

Rename
Delete
<button type="button" id="f2-button" aria-expanded="false" aria-controls="f2-menu">Options</button>
<div role="menu" id="f2-menu" aria-label="Options" hidden>
  <div tabindex="-1">Rename</div>
  <div tabindex="-1">Delete</div>
</div>

On load: pass. After opening: fail

After opening, the message key is unallowed, so it routes to NEW-49.
