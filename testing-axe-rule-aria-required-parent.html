Testing the axe rule aria-required-parent

Test cases for the axe-core rule aria-required-parent (axe-core 4.14). It's the other half of aria-required-children. That rule checks that a group contains the right items. This one checks that an item is inside the right group, such as a tab inside a tablist.

The rule only looks at elements with an explicit role attribute. A native <li> outside a list is checked by the separate listitem rule instead.

These are the roles axe checks, and the parents it accepts:

Roles checked by aria-required-parent in axe-core 4.14
RoleMust be inside one of
tabtablist
listitemlist
optionlistbox, or a group inside one
menuitem, menuitemcheckbox, menuitemradiomenu, menubar, or a group inside one
treeitemtree, or a group inside one
rowtable, grid, treegrid, rowgroup
rowgrouptable, grid, treegrid
cell, gridcell, columnheader, rowheaderrow
captionfigure, table, grid, treegrid

Elements with no role and no meaning, such as a plain <div>, are skipped on the way up. So are elements with role="none" or role="presentation", as long as the browser actually ignores that role.

This rule has no message key. Instead, axe puts the list of parent roles it would accept in data, which NEW-46 uses for the [role name] placeholder. Each case shows that list.

Every example is live in the page, so you can run the axe extension straight over it. The expected results were checked by running axe-core 4.14.1 over this page. Look in both the axe issues list and the needs review list.

Parent missing

These fail with "Required ARIA parent role not present". The item has no suitable parent anywhere above it.

A1 Tabs in a plain div

The NEW-46 example. Each tab is reported separately.

<div class="tabs">
  <button type="button" role="tab" aria-selected="true">Delivery</button>
  <button type="button" role="tab" aria-selected="false">Returns</button>
</div>

Expected result: fail

Template routing: Message key: none. Data: ["tablist"]. Routes to: NEW-46.

A2 Option on its own

Often left behind when a custom select is taken apart. Notice group is in the list, even though a group on its own isn't enough (see C2).

Expected result: fail

Template routing: Message key: none. Data: ["group", "listbox"]. Routes to: NEW-46.

Something else in between

The right parent is there, but an element with its own role sits between it and the item. Many of these are also reported by aria-required-children on the parent, so the same problem can raise two issues: NEW-46 for the item and NEW-49 for the parent.

B1 A ul between a menu and its items

The NEW-46 example. The <ul> has the role list.

  • Bold
  • Italic
<div role="menu" aria-label="Text formatting">
  <ul>
    <li role="menuitem">Bold</li>
    <li role="menuitem">Italic</li>
  </ul>
</div>

Expected result: fail

Three rules fire: this one for each item, aria-required-children for the menu, and list for the <ul>.

Template routing: Message key: none. Data: ["menu", "menubar", "group"]. Routes to: NEW-46 for each item, plus NEW-49 for the menu.

B2 A group between a tablist and its tabs

Unlike menus, a tablist doesn't allow a group in between.

<div role="tablist" aria-label="Plans">
  <div role="group" aria-label="Billing">
    <button type="button" role="tab" aria-selected="true">Monthly</button>
  </div>
</div>

Expected result: fail

Template routing: Message key: none. Data: ["tablist"]. Routes to: NEW-46, plus NEW-49 for the tablist.

B5 role="none" with aria-label

This is the fix from NEW-46, but with an aria-label added. A global ARIA attribute cancels role="none", so the <ul> is a list again.

  • Bold
<div role="menu" aria-label="Text formatting">
  <ul role="none" aria-label="Styles">
    <li role="menuitem">Bold</li>
  </ul>
</div>

Expected result: fail

Also flagged by presentation-role-conflict, aria-required-children and, as needs review, aria-prohibited-attr.

Template routing: Message key: none. Data: ["menu", "menubar", "group"]. Routes to: NEW-46, plus NEW-49 and NEW-35.

B6 role="none" with tabindex

Same again, but tabindex is what cancels role="none".

<div role="menu" aria-label="Text formatting">

  </ul>
</div>

Expected result: fail

Also flagged by presentation-role-conflict and aria-required-children.

Template routing: Message key: none. Data: ["menu", "menubar", "group"]. Routes to: NEW-46, plus NEW-49 and NEW-35.

B7 role="none" on the list itself

Sometimes role="none" is added to remove list styling or semantics, but the items keep role="listitem". Now there's no list at all.

  • Apples
<ul role="none">
  <li role="listitem">Apples</li>
</ul>

Expected result: fail

Template routing: Message key: none. Data: ["list"]. Routes to: NEW-46.

B8 Div rows inside a native table

This looks like it should pass, but browsers move <div> elements out of a <table> when they build the page. The rows end up just before the table.

Oranges
<table>
  <tbody>
    <div role="row">
      <div role="cell">Oranges</div>
    </div>
  </tbody>
</table>

Expected result: fail

View the live page's DOM in devtools to see where the row really ended up.

Template routing: Message key: none. Data: ["grid", "rowgroup", "table", "treegrid"]. Routes to: NEW-46.

C4 Nested list using a group

A group works for nested tree items (see E5) but not nested list items. Axe has code meant to allow it, but listitem only accepts list as its parent, so that code never runs. Use a nested role="list" instead (see E6).

Fruit
Apples
<div role="list">
  <div role="listitem">Fruit
    <div role="group">
      <div role="listitem">Apples</div>
    </div>
  </div>
</div>

Expected result: fail

Template routing: Message key: none. Data: ["list"]. Routes to: NEW-46.

Spelling, case and odd roles

Unlike several other ARIA rules, this one ignores case and spaces in the item's role, so these are caught.

D1 role="Tab" in capitals

Capitals
<div role="Tab" tabindex="0" aria-selected="false">Capitals</div>

Expected result: fail

Template routing: Message key: none. Data: ["tablist"]. Routes to: NEW-46.

D2 role="tab " with a trailing space

Trailing space
<div role="tab " tabindex="0" aria-selected="false">Trailing space</div>

Expected result: fail

Template routing: Message key: none. Data: ["tablist"]. Routes to: NEW-46.

D3 Parent role spelled wrong

tab-list isn't a role, so the tab has no tablist.

<div role="tab-list" aria-label="Steps">
  <button type="button" role="tab" aria-selected="true">Step one</button>
</div>

Expected result: fail

The parent is also flagged by aria-roles, and aria-prohibited-attr asks for review of its aria-label.

Template routing: Message key: none. Data: ["tablist"]. Routes to: NEW-46, plus NEW-30 for the parent.

D4 Parent with a fallback role list

Browsers skip foo and use tablist, so this tab is fine for users. Axe doesn't use fallback roles when it looks at the parent, so it fails the tab. This one is arguably a false alarm.

<div role="foo tablist" aria-label="Seasons">
  <button type="button" role="tab" aria-selected="true">Summer</button>
</div>

Expected result: fail

Template routing: Message key: none. Data: ["tablist"]. Routes to: NEW-46.

D5 List item in a directory

directory is deprecated. Axe doesn't count it as a list.

Staff
<div role="directory">
  <div role="listitem">Staff</div>
</div>

Expected result: fail

The parent is also flagged by aria-deprecated-role.

Template routing: Message key: none. Data: ["list"]. Routes to: NEW-46, plus NEW-32 for the parent.

Not caught by this rule

F1 Tab with a fallback role list

Browsers use the first role they know, so Chrome treats this as a tab with no tablist. Axe only checks a role attribute that holds exactly one role, so it skips this element. Nothing else flags it either.

Delivery
<div role="tab button" tabindex="0">Delivery</div>

Expected result: passes, but it's broken (check manually)

Template routing: No result, so nothing to route.

F2 Menu item taken out of its menu by aria-owns

In the code, Paste is inside the menu. But the toolbar div owns it, so browsers move it out of the menu. Axe checks the code, not where aria-owns puts the item, so it passes.

Paste
Cut
<div role="menu" aria-label="Edit">
  <div role="menuitem" id="f2-paste">Paste</div>
  <div role="menuitem">Cut</div>
</div>
<div class="toolbar" aria-owns="f2-paste"></div>

Expected result: passes, but it's broken (check manually)

Chrome's accessibility tree shows Paste under the toolbar, not the menu.

Template routing: No result, so nothing to route.

F3 Tab taken out of its tablist by aria-owns

Same idea, but this time the tab is moved into a list. This rule passes the tab, and the problem is reported on the list instead.

<div role="tablist" aria-label="Accounts">
  <button type="button" role="tab" id="f3-tab" aria-selected="true">Personal</button>
</div>
<div role="list" aria-owns="f3-tab"></div>

Expected result: flagged by aria-required-children instead

Template routing: Message key: unallowed. Routes to: NEW-49, not NEW-46.

F4 Focusable wrapper in between

This rule skips the wrapper because it has no role, so the menu item passes. aria-required-children flags the wrapper on the menu instead.

Email
<div role="menu" aria-label="Share">
  <div tabindex="0">
    <div role="menuitem">Email</div>
  </div>
</div>

Expected result: flagged by aria-required-children instead

Template routing: Message key: unallowed. Routes to: NEW-49, not NEW-46.

F5 A native li with no list

No role attribute, so this rule doesn't look at it. The listitem rule catches it instead.

  • Orphan item
    • <li>Orphan item</li>

    Expected result: flagged by listitem instead

    Template routing: Not an ARIA rule, so outside this template set.

    Changes after interaction

    Axe only sees the page as it is when you run it. These pass on page load. Activate each button, then run axe again.

    G1 Menu that's hidden until opened

    Axe doesn't test hidden content. Open the menu and the <ul> between the menu and its items is found.

    • Rename
    • Delete
    <button type="button" id="g1-button" aria-expanded="false" aria-controls="g1-menu">Options</button>
<div role="menu" id="g1-menu" aria-label="Options" hidden>
  <ul>
    <li role="menuitem">Rename</li>
    <li role="menuitem">Delete</li>
  </ul>
</div>

    On load: pass. After opening: fail

    After opening, the items route to NEW-46 and the menu routes to NEW-49.

    G2 New items added in the wrong place

    On load, the list is fine. The button adds a new item, but the script puts it after the list instead of inside it.

    First result
    <div id="g2-wrap">
  <div role="list" id="g2-list">
    <div role="listitem">First result</div>
  </div>
</div>
<button type="button" id="g2-more">Show more</button>

    On load: pass. After adding: fail

    After adding, the new item routes to NEW-46 with data ["list"].
