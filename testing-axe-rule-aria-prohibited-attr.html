Testing the axe rule aria-prohibited-attr

Test cases for the axe-core rule aria-prohibited-attr (axe-core 4.14). Some roles can't be given a name. ARIA prohibits aria-label and aria-labelledby on them, and many screen readers ignore the name.

These include elements with no role, like <div> and <span>, and text-level elements, like <p>, <strong>, <code>, <mark>, <del> and <sup>. It also includes role="none" and role="presentation".

The key thing to know: the rule only fails an element if it's empty. If the element has any text inside it, the result is needs review, because the text is still read even if the name is ignored. So most real-world cases show up under needs review.

Each case also shows the axe message key and which Intopia issue template the result would go to under the current assembly rules. Results on this page were checked in Chrome.

axe-core results: See the HTML report from running axe-core 4.14.0 over this page.

Every example is live in the page, so you can run the axe extension straight over it. The expected results were checked by running axe-core 4.14.1 over this page. Look in both the axe issues list and the needs review list.

Empty elements with a prohibited name

These fail. With no text inside, the name is the only content, so if it's ignored nothing is announced.

A1 An empty div with aria-label

Often used for a map or chart drawn by a script.

<div aria-label="Map of our stores"></div>

Expected result: fail

Template routing: Message key: noRoleSingular. Routes to: NEW-44.

A2 An empty paragraph with aria-label

<p aria-label="Note"></p>

Expected result: fail

Template routing: Message key: noRoleSingular. Routes to: NEW-44.

A3 An empty em with aria-label

<em aria-label="stress"></em>

Expected result: fail

Template routing: Message key: noRoleSingular. Routes to: NEW-44.

A4 role="presentation" with aria-label

<div role="presentation" aria-label="Layout"></div>

Expected result: fail

Template routing: Message key: noRoleSingular. Routes to: NEW-44.

A5 A div that only contains a decorative image

The image has alt="", so there's still no text.

<div aria-label="Company logo">
  <img src="data:image/gif;base64,R0lGODlhAQABAAAAACw=" alt="" width="20" height="20">
</div>

Expected result: fail

Template routing: Message key: noRoleSingular. Routes to: NEW-44.

Elements with text and a prohibited name

These are needs review, with the message "aria-label attribute is not well supported on ... elements with no valid role attribute". The text is read, but the name is likely to be ignored.

B1 A span with aria-label

The name is meant to add context, but it's likely to be ignored, so screen reader users just hear "$25".

<span aria-label="Price">$25</span>

Expected result: needs review

Template routing: Needs review, message key: noRoleSingular. Routes to: NEW-44.

Needs review, with no template

Two aria-labelledby cases have their own message keys, and the rule map gives them no template on purpose.

C1 aria-labelledby pointing to visible text

The referenced text is already on the page, so nothing is lost if the name is ignored.

Order total

$40

<span id="c1-label">Order total</span>
<p aria-labelledby="c1-label">$40</p>

Expected result: needs review

Template routing: Needs review, message key: visibleLabelSingular. Routes to: no template (decided, because the text is read anyway).

C2 aria-labelledby pointing to a missing ID

$40

<p aria-labelledby="c2-missing">$40</p>

Expected result: needs review

This also shows up under aria-valid-attr-value for the missing ID.

Template routing: Needs review, message key: unresolvedLabel. Routes to: no template (decided). The aria-valid-attr-value result routes to NEW-36.

Ways to pass

Control cases.

D1 An aria-label with only spaces

Ignored, because there's no actual name.

Plain text
<div aria-label="   ">Plain text</div>

Expected result: pass (valid)

D2 A region with a name

Free delivery this week.
<div role="region" aria-label="Special offers">Free delivery this week.</div>

Expected result: pass (valid)

D3 An image role with a name

**** 
<span role="img" aria-label="Four stars">****</span>

Expected result: pass (valid)

D4 A paragraph with role="note"

The note role can be named.

Save your work often.

<p role="note" aria-label="Tip">Save your work often.</p>

Expected result: pass (valid)

D5 aria-describedby on a span

Only naming is prohibited. A description is fine.

Delivery fee Free over $50 
<span aria-describedby="d5-desc">Delivery fee</span>
<span id="d5-desc">Free over $50</span>

Expected result: pass (valid)

Changes after interaction

Axe only sees the page as it is when you run it. These pass on page load. Activate each button, then run axe again.

E1 A loading message that leaves an empty element behind

On load, the span has text, so it's needs review. The button clears the text, which leaves only the aria-label, and it becomes a fail.

Loading... 
<button type="button" id="e1-button">Finish loading</button>
<span id="e1-status" aria-label="Loading complete">Loading...</span>

On load: needs review. After clicking: fail

After clicking, the message key is still noRoleSingular, so it routes to NEW-44 as a fail rather than needs review.
