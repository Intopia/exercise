Testing the axe rule aria-text

Test cases for the axe-core rule aria-text (axe-core 4.14). The rule checks that an element with role="text" doesn't contain anything that can receive focus, such as a link, button or form control.

role="text" isn't a WAI-ARIA role. Safari supports it, and uses it to read text that's split across several elements as one phrase. Chrome ignores it. Where it's supported, everything inside the element is read as plain text, including links and controls.

The rule runs one check, no-focusable-content. It only counts elements that can receive focus and have an interactive role. This is a best practice rule, not a WCAG requirement.

Some cases include results from testing with VoiceOver in Safari and Chrome on macOS.

axe-core results: See the HTML report from running axe-core 4.14.0 over this page.

Every example is live in the page, so you can run the axe extension straight over it. The expected results were checked by running axe-core 4.14.1 over this page. Look in both the axe issues list and the needs review list.

Focusable content inside role="text"

These fail with "Element has focusable descendants".

A1 Link

$24.99 per month. See all prices 
<span role="text">$24.99 per month. <a href="#a1">See all prices</a></span>

Expected result: fail

Tested with VoiceOver in Safari: reading reads "$24.99 per month. See all prices" as one phrase, with no "link". Pressing Tab announces "link, See all prices" correctly. So the link is only lost when reading.

Template routing: Message key: none. Routes to: NEW-34.

Focusable content with tabindex="-1"

These fail with a different message: a negative tabindex doesn't stop assistive technologies reaching the element.

B1 Link with tabindex="-1"

$19.99 per month. See all prices 
<span role="text">$19.99 per month. <a href="#b1" tabindex="-1">See all prices</a></span>

Expected result: fail

Tested with VoiceOver in Safari: Tab skips the link, but reading still reaches it, as plain text. So tabindex="-1" makes things worse: keyboard users can't reach it either.

Template routing: Message key: notHidden. Routes to: NEW-34.

B2 Button with tabindex="-1"

Out of stock. 
<span role="text">Out of stock. <button type="button" tabindex="-1">Notify me</button></span>

Expected result: fail

Template routing: Message key: notHidden. Routes to: NEW-34.

Focusable, but not counted

These can receive focus, but they don't have an interactive role, so axe doesn't count them.

D1 Focusable span

Read our terms and conditions before you buy. 
<span role="text">Read our <span tabindex="0">terms and conditions</span> before you buy.</span>

Expected result: passes, but it's broken (check manually)

Tested with VoiceOver in Safari: reading is fine ("Read our terms and conditions before you buy."), but Tab announces "terms and conditions, empty group" in both Safari and Chrome. That's a problem with tabindex on a span, not with role="text".

Template routing: No result, so nothing to route.

Flagged by a different rule instead

E1 role="text" on the link itself

Nothing inside can receive focus, so this rule passes it. But the role replaces the link's own role.

Now $24.99 
<a href="#e1" role="text">Now <span>$24.99</span></a>

Expected result: flagged by aria-allowed-role instead

Not yet tested with VoiceOver.

Template routing: Routes to: NEW-31.

<button type="button" role="text">Buy <span>$24.99</span></button>

Expected result: flagged by aria-allowed-role instead

Template routing: Routes to: NEW-31.

Ways to pass

Control cases.

F1 Split text joined with role="text"

This is what role="text" is for.

Now $24.99 per month

<p><span role="text">Now <strong>$24.99</strong> per month</span></p>

Expected result: pass (valid)

F2 Link moved outside role="text"

$24.99 per month. See all prices 
<span role="text">$24.99 per month.</span> <a href="#f2">See all prices</a>

Expected result: pass (valid)

Tested with VoiceOver in Safari: reading reads "$24.99 per month." then "link, See all prices".

F3 Link hidden with display: none

A link that isn't displayed can't receive focus.

$9.99 per month. See all prices 
<span role="text">$9.99 per month. <a href="#f3" style="display: none;">See all prices</a></span>

Expected result: pass (valid)

F4 Empty element

<span role="text"></span>

Expected result: pass (valid)

Changes after interaction

Axe only sees the page as it is when you run it. These pass on page load. Activate each button, then run axe again.

G1 A link added by a script

On load, the price has no link. The button adds an "offer" link inside the role="text" span.

Now $24.99 per month.

<button type="button" id="g1-button">Show offer</button>
<p><span role="text" id="g1-price">Now <strong>$24.99</strong> per month.</span></p>

On load: pass. After showing the offer: fail

After the click, the message key is none, so it routes to NEW-34.

G2 A link revealed by a script

On load, the link is hidden with display: none, so it can't receive focus. The button shows it.

Free delivery over $50. Details

<button type="button" id="g2-button">Show details link</button>
<p><span role="text">Free delivery over $50. <a href="#g2" id="g2-link" style="display: none;">Details</a></span></p>

On load: pass. After showing the link: fail

After the click, the message key is none, so it routes to NEW-34.
