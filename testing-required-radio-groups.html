Testing required on radio groups

A group of radio buttons can be a fieldset, a div with role="group", or a div with role="radiogroup". Only radiogroup supports aria-required. The examples below show what each technique does and does not do. Submit each form to test native validation.

Every example has a coloured box showing how to read it:

Invalid: not allowed by the HTML or ARIA specifications.

Poor practice: allowed, but not recommended.

Acceptable: allowed, and does part or all of the job. The box says what it does and does not give you.

Control: a baseline with no requirement defined.

Controls

Baselines with no requirement defined.

Example 1: fieldset

Control: A fieldset with a legend. No requirement is defined.

Which is your favourite pet?

HTML markup 
<fieldset>
  <legend>Which is your favourite pet?</legend>
  <div>
    <input type="radio" id="r1-dog" name="r1" value="dog">
    <label for="r1-dog">Dog</label>
  </div>
  <div>
    <input type="radio" id="r1-cat" name="r1" value="cat">
    <label for="r1-cat">Cat</label>
  </div>
  <div>
    <input type="radio" id="r1-rabbit" name="r1" value="rabbit">
    <label for="r1-rabbit">Rabbit</label>
  </div>
</fieldset>

aria-required on the container

Only radiogroup supports aria-required. It is not supported on the group role.

required on the container

required is an HTML attribute that is only valid on input, select and textarea. A role does not add HTML attributes.

Error states

The group is marked as invalid after a failed submission. The error text is pre-set, so no JavaScript is needed.

Example 21: aria-invalid on the fieldset

Poor practice: aria-invalid is deprecated as a global attribute in ARIA 1.2 and is not supported on the group role. The error text is not linked to the group.
