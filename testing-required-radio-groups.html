Testing required on radio groups

A group of radio buttons can be a fieldset, a div with role="group", or a div with role="radiogroup". Only radiogroup supports aria-required. The examples below show what each technique does and does not do.

Simplest approach: for any group of checkboxes or radios, add the requirement to the group's name, or add it as a hint. See Recommended practice.

Every example has a coloured box showing how to read it:

Invalid: not allowed by the HTML or ARIA specifications.

Poor practice: allowed, but not recommended.

Acceptable: allowed, and does part or all of the job. The box says what it does and does not give you.

Control: a baseline with no requirement defined.

1. Controls

Baselines with no requirement defined.

Example 1.1: fieldset

Control: A fieldset with a legend. No requirement is defined.

Which is your favourite pet?
HTML markup 
<fieldset>
  <legend>Which is your favourite pet?</legend>
  <div>
    <input type="radio" id="r1-dog" name="r1" value="dog">
    <label for="r1-dog">Dog</label>
  </div>
  <div>
    <input type="radio" id="r1-cat" name="r1" value="cat">
    <label for="r1-cat">Cat</label>
  </div>
  <div>
    <input type="radio" id="r1-rabbit" name="r1" value="rabbit">
    <label for="r1-rabbit">Rabbit</label>
  </div>
</fieldset>

2. Requirement as text in the group's name

The requirement is written in the visible text as part of the group's name: the legend, or the labelling element.

Example 2.1: fieldset

Acceptable: The requirement is in the group's accessible name, so it is available in text and associated with the group (WCAG 1.3.1 and 3.3.2). It does not expose a required state to assistive technology.

Which is your favourite pet? (required)

4. Requirement as a hint

Example 4.1: fieldset

Acceptable: The hint is associated with the group with aria-describedby, so the requirement is available in text (WCAG 1.3.1 and 3.3.2). It does not expose a required state to assistive technology.

5. aria-required on the container

Only radiogroup supports aria-required. It is not supported on the group role.

Example 5.1: On the fieldset

Invalid: aria-required is not supported on the group role, which fieldset has implicitly.

Which is your favourite pet?
HTML markup 
<fieldset aria-required="true">
  <legend>Which is your favourite pet?</legend>
  <div>
    <input type="radio" id="r11-dog" name="r11" value="dog">
    <label for="r11-dog">Dog</label>
  </div>
  <div>
    <input type="radio" id="r11-cat" name="r11" value="cat">

  </div>
  <div>
    <input type="radio" id="r11-rabbit" name="r11" value="rabbit">

</fieldset>

Invalid: aria-required is not supported on the group role.

Example 5.3: On the div with role="radiogroup"

Acceptable: radiogroup is the only group role that supports aria-required, so this exposes a required state to assistive technology. It adds nothing visible, so use it together with the group's name or a hint, not instead of them.

6. required on the container

None of these options is valid.

7. Requirement on the radios

Attributes on the radio buttons themselves. Radios that share a name form one set.

None of these options is good practice.

Example 7.1: aria-required on each radio

Invalid: aria-required is not supported on the radio role.

Which is your favourite pet?
HTML markup 
<fieldset>
  <legend>Which is your favourite pet?</legend>
  <div>
    <input type="radio" id="r17-dog" name="r17" value="dog" aria-required="true">
    <label for="r17-dog">Dog</label>
  </div>
  <div>
    <input type="radio" id="r17-cat" name="r17" value="cat" aria-required="true">
    <label for="r17-cat">Cat</label>
  </div>
  <div>
    <input type="radio" id="r17-rabbit" name="r17" value="rabbit" aria-required="true">
    <label for="r17-rabbit">Rabbit</label>
  </div>
</fieldset>

Example 7.2: aria-required on one radio only

Invalid: aria-required is not supported on the radio role, and one radio does not set a requirement for the group.

Which is your favourite pet?
HTML markup 
<fieldset>
  <legend>Which is your favourite pet?</legend>
  <div>
    <input type="radio" id="r18-dog" name="r18" value="dog" aria-required="true">
    <label for="r18-dog">Dog</label>
  </div>
  <div>
    <input type="radio" id="r18-cat" name="r18" value="cat">
    <label for="r18-cat">Cat</label>
  </div>
  <div>
    <input type="radio" id="r18-rabbit" name="r18" value="rabbit">
    <label for="r18-rabbit">Rabbit</label>
  </div>
</fieldset>

Example 7.3: required on every radio

Poor practice: Native validation blocks submission until one radio is chosen. It relies on the browser's built-in message, which you can't word or style, and which only appears on submit.

Which is your favourite pet?
HTML markup 
<fieldset>
  <legend>Which is your favourite pet?</legend>
  <div>
    <input type="radio" id="r19-dog" name="r19" value="dog" required>
    <label for="r19-dog">Dog</label>
  </div>
  <div>
    <input type="radio" id="r19-cat" name="r19" value="cat" required>
    <label for="r19-cat">Cat</label>
  </div>
  <div>
    <input type="radio" id="r19-rabbit" name="r19" value="rabbit" required>
    <label for="r19-rabbit">Rabbit</label>
  </div>
</fieldset>

Example 7.4: required on one radio only

Poor practice: Native validation treats the whole named set as required, but the attribute is on one radio only, so users of assistive technology may take it to mean that one radio is required, not the group. It relies on the browser's built-in message, which you can't word or style, and which only appears on submit.

Which is your favourite pet?
HTML markup 
<fieldset>
  <legend>Which is your favourite pet?</legend>
  <div>
    <input type="radio" id="r20-dog" name="r20" value="dog" required>
    <label for="r20-dog">Dog</label>
  </div>
  <div>
    <input type="radio" id="r20-cat" name="r20" value="cat">
    <label for="r20-cat">Cat</label>
  </div>
  <div>
    <input type="radio" id="r20-rabbit" name="r20" value="rabbit">
    <label for="r20-rabbit">Rabbit</label>
  </div>
</fieldset>
