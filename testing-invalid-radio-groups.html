Testing aria-invalid on radio groups

When a group of radios is in error, assistive technology needs to be told that the group is invalid. The examples below test how to expose that invalid state. Every state is pre-set in the markup, so no JavaScript is needed.

Simplest approach: add aria-invalid="true" to a div with role="radiogroup". See Recommended practice.

Every example has a coloured box showing how to read it:

Poor practice: allowed, but not recommended.

Acceptable: allowed, and does part or all of the job. The box says what it does and does not give you.

Control: a baseline.

1. Controls

Baselines. The same visible error text is in every example on this page, and nothing links it to the group, so the examples test the invalid state only.

Example 1.1: fieldset

Control: The group with the error text shown and no invalid state.

Which is your favourite pet?

Error: Choose one pet.

HTML markup 
<fieldset>
  <legend>Which is your favourite pet?</legend>
  <p class="error">Error: Choose one pet.</p>
  <div>
    <input type="radio" id="r1-dog" name="r1" value="dog">
    <label for="r1-dog">Dog</label>
  </div>
  <div>
    <input type="radio" id="r1-cat" name="r1" value="cat">
    <label for="r1-cat">Cat</label>
  </div>
  <div>
    <input type="radio" id="r1-rabbit" name="r1" value="rabbit">
    <label for="r1-rabbit">Rabbit</label>
  </div>
</fieldset>

2. aria-invalid on the group

aria-invalid marks the group as being in error. It is supported on radiogroup, not on the group role.

Example 2.1: On the fieldset

Poor practice: aria-invalid is deprecated as a global attribute in ARIA 1.2 and is not supported on the group role.

Which is your favourite pet?

Error: Choose one pet.

HTML markup 
<fieldset aria-invalid="true">
  <legend>Which is your favourite pet?</legend>
  <p class="error">Error: Choose one pet.</p>
  <div>
    <input type="radio" id="r4-dog" name="r4" value="dog">
    <label for="r4-dog">Dog</label>
  </div>
  <div>
    <input type="radio" id="r4-cat" name="r4" value="cat">
    <label for="r4-cat">Cat</label>
  </div>
  <div>
    <input type="radio" id="r4-rabbit" name="r4" value="rabbit">
    <label for="r4-rabbit">Rabbit</label>
  </div>
</fieldset>

3. aria-invalid on the radios

aria-invalid on the radios themselves.

None of these options is good practice.

Example 3.1: aria-invalid on each radio

Poor practice: aria-invalid is not supported on the radio role. Every radio is marked invalid.

Which is your favourite pet?

Error: Choose one pet.

HTML markup 
<fieldset>
  <legend>Which is your favourite pet?</legend>
  <p class="error">Error: Choose one pet.</p>
  <div>
    <input type="radio" id="r7-dog" name="r7" value="dog" aria-invalid="true">
    <label for="r7-dog">Dog</label>
  </div>
  <div>
    <input type="radio" id="r7-cat" name="r7" value="cat" aria-invalid="true">
    <label for="r7-cat">Cat</label>
  </div>
  <div>
    <input type="radio" id="r7-rabbit" name="r7" value="rabbit" aria-invalid="true">
    <label for="r7-rabbit">Rabbit</label>
  </div>
</fieldset>
