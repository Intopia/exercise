Testing aria-pressed

aria-pressed indicates the current "pressed" state of a toggle button, for example, a bold or italic button in a text editor toolbar that stays visually active once selected. It is intended for use on a real <button> element, or an element with role="button".

Example 1: Static

This button does not respond to interaction. It is included to let you inspect a fixed aria-pressed="true" state.

Expected result: the accessibility tree should show pressed: true for this button, and this never changes.

HTML markup 
<button aria-pressed="true">
  Bold
</button>

Example 2: Interactive

This button starts unpressed. Activate it to toggle aria-pressed between false and true, and to bold or unbold the sample sentence below it.

The quick brown fox jumps over the lazy dog.

Expected result: the accessibility tree should show pressed: false initially, and pressed: true once activated. This should toggle back and forth each time the button is activated, in sync with the sample sentence becoming bold or returning to normal weight.

HTML markup 
<button id="toggle-button" aria-pressed="false">
  Bold
</button>
<p id="toggle-sample">The quick brown fox jumps over the lazy dog.</p>

Example 3: Mixed state

aria-pressed supports a third value, "mixed", distinct from both true and false. This is used when the pressed state is genuinely ambiguous, for example, a Bold button in a toolbar when the current text selection contains a mix of bold and non-bold text.

The sentence below starts with a mix of bold and non-bold words, standing in for a selection with mixed formatting. Activating the button resolves that ambiguity: the first click makes everything bold and sets aria-pressed="true", matching how most real editors handle clicking a control while its state is mixed. After that, it behaves as a normal two-state toggle, matching Example 2.

The quick brown fox jumps over the lazy dog.

Expected result: worth confirming directly, whether "mixed" is announced distinctly from true or false (for example, as "bold, mixed" rather than "bold, pressed") is not something to assume, this has historically varied across screen reader and browser combinations.

HTML markup 
<button id="mixed-button" aria-pressed="mixed">
  Bold
</button>
<p id="mixed-sample">The <b>quick brown</b> fox jumps over the lazy dog.</p>

Example 4: misuse, no button role

This element has aria-pressed but no button semantics at all, it is a plain <div> with no role. This is a common real-world mistake, toggle-style controls are sometimes built as styled links or bare elements without the underlying role needed to support a pressed state correctly.

Bold

Expected result: worth confirming directly, since this element has no role at all, aria-pressed may not be exposed or announced consistently. The correct fix is adding role="button" and tabindex="0", or using a real <button> element instead.

HTML markup 
<div aria-pressed="false">
  Bold
</div>

Note for testing: confirm all four results above with your standard browser and screen reader combinations before treating them as settled. The mixed state (Example 3) and the misuse case (Example 4) are both areas where behaviour has not been verified here and may not be consistent.
