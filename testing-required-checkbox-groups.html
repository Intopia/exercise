Testing required on checkbox groups

There is no valid native HTML or ARIA way to mark a checkbox group as at least one required. The examples below show what each technique does and does not do. Submit each form to test native validation.

Every example has a coloured box showing how to read it:

Invalid: not allowed by the HTML or ARIA specifications.

Poor practice: allowed, but not recommended.

Acceptable: allowed, and does part or all of the job. The box says what it does and does not give you.

Control: a baseline with no requirement defined.

Controls

Baselines with no requirement defined.

Example 1: fieldset

Control: A fieldset with a legend. No requirement is defined.

Which pets do you have?

HTML markup 
<fieldset>
  <legend>Which pets do you have?</legend>
  <div>
    <input type="checkbox" id="c1-dog" name="c1" value="dog">
    <label for="c1-dog">Dog</label>
  </div>
  <div>
    <input type="checkbox" id="c1-cat" name="c1" value="cat">
    <label for="c1-cat">Cat</label>
  </div>
  <div>
    <input type="checkbox" id="c1-rabbit" name="c1" value="rabbit">
    <label for="c1-rabbit">Rabbit</label>
  </div>
</fieldset>

required on the container

required is an HTML attribute that is only valid on input, select and textarea. A role does not add HTML attributes.

None of these options is valid.

Requirement on the checkboxes

Attributes on the checkboxes themselves. Each checkbox is its own control, so a requirement on a checkbox applies to that checkbox only.

None of these options is good practice.

Example 12: aria-required on each checkbox

Poor practice: It marks every checkbox as required, which implies all of them must be ticked.

Which pets do you have?

  <div>
    <input type="checkbox" id="c12-dog" name="c12" value="dog" aria-required="true">
    <label for="c12-dog">Dog</label>
  </div>
  <div>
    <input type="checkbox" id="c12-cat" name="c12" value="cat" aria-required="true">

Error states

The group is marked as invalid after a failed submission. The error text is pre-set, so no JavaScript is needed.

Example 16: aria-invalid on the fieldset

Poor practice: aria-invalid is deprecated as a global attribute in ARIA 1.2 and is not supported on the group role. The error text is not linked to the group.

Which pets do you have?

Error: Choose at least one pet.

<fieldset aria-invalid="true">
  <legend>Which pets do you have?</legend>
  <p class="error">Error: Choose at least one pet.</p>
  <div>

    <label for="c16-dog">Dog</label>

Example 17: aria-invalid on each checkbox

Acceptable: aria-invalid is valid on checkbox. Each checkbox is marked invalid and linked to the error with aria-describedby.
