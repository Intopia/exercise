Testing required on checkbox groups

There is no valid native HTML or ARIA way to mark a checkbox group as at least one required. The examples below show what each technique does and does not do.

Simplest approach: for any group of checkboxes or radios, add the requirement to the group's name, or add it as a hint.

Every example has a coloured box below it showing how to read it:

Invalid: not allowed by the HTML or ARIA specifications.

Poor practice: allowed, but not recommended.

Recommended: the approach to use.

1. Requirement as text outside the group

The requirement is written in the visible text outside the group.

Example 1.1: Text outside the group

A paragraph before the fieldset gives the requirement.

Required: Choose at least one pet.

Which pets do you have?

Poor practice: Nothing associates the paragraph with the group.

HTML markup 
<p>Required: Choose at least one pet.</p>
<fieldset>
  <legend>Which pets do you have?</legend>
  <div>
    <input type="checkbox" id="c5-dog" name="c5" value="dog">
    <label for="c5-dog">Dog</label>
  </div>
  <div>
    <input type="checkbox" id="c5-cat" name="c5" value="cat">
    <label for="c5-cat">Cat</label>
  </div>
  <div>
    <input type="checkbox" id="c5-rabbit" name="c5" value="rabbit">
    <label for="c5-rabbit">Rabbit</label>
  </div>
</fieldset>

2. aria-required on the container

aria-required is not supported on the group role, which fieldset has implicitly.

Example 2.1: On the fieldset

aria-required="true" is added to the fieldset.

Which pets do you have?

Invalid: aria-required is not supported on the group role, which fieldset has implicitly.

HTML markup 
<fieldset aria-required="true">
  <legend>Which pets do you have?</legend>
  <div>
    <input type="checkbox" id="c8-dog" name="c8" value="dog">
    <label for="c8-dog">Dog</label>
  </div>
  <div>
    <input type="checkbox" id="c8-cat" name="c8" value="cat">
    <label for="c8-cat">Cat</label>
  </div>
  <div>
    <input type="checkbox" id="c8-rabbit" name="c8" value="rabbit">
    <label for="c8-rabbit">Rabbit</label>
  </div>
</fieldset>

Example 2.2: On the div with role="group"

aria-required="true" is added to the div with role="group".

Which pets do you have?

Invalid: aria-required is not supported on the group role.

HTML markup 
<div role="group" aria-labelledby="c9-label" aria-required="true">
  <p id="c9-label">Which pets do you have?</p>
  <div>
    <input type="checkbox" id="c9-dog" name="c9" value="dog">

  </div>
  <div>
    <input type="checkbox" id="c9-rabbit" name="c9" value="rabbit">

  </div>
</div>

3. required on the container

required is an HTML attribute that is only valid on input, select and textarea. A role does not add HTML attributes.

Example 3.1: On the fieldset

The required attribute is added to the fieldset.

Which pets do you have?

Invalid: required is only valid on input, select and textarea.

HTML markup 
<fieldset required>
  <legend>Which pets do you have?</legend>
  <div>
    <input type="checkbox" id="c10-dog" name="c10" value="dog">
    <label for="c10-dog">Dog</label>
  </div>
  <div>
    <input type="checkbox" id="c10-cat" name="c10" value="cat">
    <label for="c10-cat">Cat</label>
  </div>
  <div>
    <input type="checkbox" id="c10-rabbit" name="c10" value="rabbit">
    <label for="c10-rabbit">Rabbit</label>
  </div>
</fieldset>

Example 3.2: On the div with role="group"

The required attribute is added to the div with role="group".

Which pets do you have?

Invalid: required is only valid on input, select and textarea. A role does not add HTML attributes.

HTML markup 
<div role="group" aria-labelledby="c11-label" required>
  <p id="c11-label">Which pets do you have?</p>
  <div>
    <input type="checkbox" id="c11-dog" name="c11" value="dog">
    <label for="c11-dog">Dog</label>
  </div>
  <div>
    <input type="checkbox" id="c11-cat" name="c11" value="cat">

None of these options is valid.

4. Requirement on the checkboxes

Attributes on the checkboxes themselves. Each checkbox is its own control, so a requirement on a checkbox applies to that checkbox only.

Example 4.1: aria-required on each checkbox

Every checkbox has aria-required="true".

Which pets do you have?

Poor practice: It marks every checkbox as required, which implies all of them must be ticked.

HTML markup 
<fieldset>
  <legend>Which pets do you have?</legend>
  <div>
    <input type="checkbox" id="c12-dog" name="c12" value="dog" aria-required="true">
    <label for="c12-dog">Dog</label>
  </div>
  <div>
    <input type="checkbox" id="c12-cat" name="c12" value="cat" aria-required="true">
    <label for="c12-cat">Cat</label>
  </div>
  <div>
    <input type="checkbox" id="c12-rabbit" name="c12" value="rabbit" aria-required="true">
    <label for="c12-rabbit">Rabbit</label>
  </div>
</fieldset>

Example 4.2: aria-required on one checkbox only

Only the first checkbox has aria-required="true".

Which pets do you have?

Poor practice: It marks only that checkbox as required. It says nothing about the group.

HTML markup 
<fieldset>
  <legend>Which pets do you have?</legend>
  <div>
    <input type="checkbox" id="c13-dog" name="c13" value="dog" aria-required="true">
    <label for="c13-dog">Dog</label>
  </div>
  <div>
    <input type="checkbox" id="c13-cat" name="c13" value="cat">
    <label for="c13-cat">Cat</label>
  </div>
  <div>
    <input type="checkbox" id="c13-rabbit" name="c13" value="rabbit">
    <label for="c13-rabbit">Rabbit</label>
  </div>
</fieldset>

Example 4.3: required on each checkbox

Every checkbox has required.

Which pets do you have?

Poor practice: Native validation forces every checkbox to be ticked before the form submits.

HTML markup 
<fieldset>
  <legend>Which pets do you have?</legend>
  <div>
    <input type="checkbox" id="c14-dog" name="c14" value="dog" required>
    <label for="c14-dog">Dog</label>
  </div>
  <div>
    <input type="checkbox" id="c14-cat" name="c14" value="cat" required>
    <label for="c14-cat">Cat</label>
  </div>
  <div>
    <input type="checkbox" id="c14-rabbit" name="c14" value="rabbit" required>
    <label for="c14-rabbit">Rabbit</label>
  </div>
</fieldset>

Example 4.4: required on one checkbox only

Only the first checkbox has required.

Which pets do you have?

Poor practice: Native validation only forces that one checkbox to be ticked. It does not make the group require at least one.

HTML markup 
<fieldset>
  <legend>Which pets do you have?</legend>
  <div>
    <input type="checkbox" id="c15-dog" name="c15" value="dog" required>
    <label for="c15-dog">Dog</label>

  </div>
  <div>
    <input type="checkbox" id="c15-rabbit" name="c15" value="rabbit">
    <label for="c15-rabbit">Rabbit</label>
  </div>
</fieldset>

None of these options is good practice.

5. Requirement as text in the group's name

The requirement is written in the visible text as part of the group's name: the legend, or the labelling element.

Example 5.1: fieldset

The legend includes (required).

Which pets do you have? (required)

Recommended: The requirement is in the group's accessible name, so it is available in text and associated with the group (WCAG 1.3.1 and 3.3.2). It does not expose a required state to assistive technology.

HTML markup 
<fieldset>
  <legend>Which pets do you have? (required)</legend>
  <div>
    <input type="checkbox" id="c3-dog" name="c3" value="dog">
    <label for="c3-dog">Dog</label>
  </div>
  <div>
    <input type="checkbox" id="c3-cat" name="c3" value="cat">
    <label for="c3-cat">Cat</label>
  </div>
  <div>
    <input type="checkbox" id="c3-rabbit" name="c3" value="rabbit">
    <label for="c3-rabbit">Rabbit</label>
  </div>
</fieldset>

Example 5.2: div with role="group"

The labelling element includes (required).

Which pets do you have? (required)

Recommended: The requirement is in the group's accessible name, so it is available in text and associated with the group (WCAG 1.3.1 and 3.3.2). It does not expose a required state to assistive technology.

HTML markup 
<div role="group" aria-labelledby="c4-label">
  <p id="c4-label">Which pets do you have? (required)</p>
  <div>
    <input type="checkbox" id="c4-dog" name="c4" value="dog">
    <label for="c4-dog">Dog</label>
  </div>
  <div>
    <input type="checkbox" id="c4-cat" name="c4" value="cat">
    <label for="c4-cat">Cat</label>
  </div>
  <div>
    <input type="checkbox" id="c4-rabbit" name="c4" value="rabbit">

  </div>
</div>

6. Requirement as a hint

The requirement is a hint linked to the group with aria-describedby.

Example 6.1: fieldset

A hint paragraph inside the group is linked to it with aria-describedby.

Which pets do you have?

Choose at least one pet.

Recommended: The hint is associated with the group with aria-describedby, so the requirement is available in text (WCAG 1.3.1 and 3.3.2). It does not expose a required state to assistive technology.

HTML markup 
<fieldset aria-describedby="c6-hint">
  <legend>Which pets do you have?</legend>
  <p id="c6-hint">Choose at least one pet.</p>
  <div>
    <input type="checkbox" id="c6-dog" name="c6" value="dog">
    <label for="c6-dog">Dog</label>
  </div>
  <div>
    <input type="checkbox" id="c6-cat" name="c6" value="cat">
    <label for="c6-cat">Cat</label>
  </div>
  <div>
    <input type="checkbox" id="c6-rabbit" name="c6" value="rabbit">
    <label for="c6-rabbit">Rabbit</label>
  </div>
</fieldset>

Example 6.2: div with role="group"
