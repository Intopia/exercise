Testing the axe rule aria-required-attr

Test cases for the axe-core rule aria-required-attr (axe-core 4.14). Some roles need a state or value to make sense. A checkbox needs to say whether it's checked, and a heading needs a level. The rule checks that elements with these roles have the attributes they need.

Roles with required attributes in axe-core 4.14
RoleRequires
checkbox, radio, switch, menuitemcheckbox, menuitemradioaria-checked
comboboxaria-expanded and aria-controls
headingaria-level
slider, meter, scrollbar, separatoraria-valuenow

The rule only checks explicit roles. Native elements, like <input type="checkbox"> and <h2>, already provide these states, so they always pass. An empty value counts as missing.

Each case also shows the axe message key and which Intopia issue template the result would go to under the current assembly rules. Results on this page were checked in Chrome.

axe-core results: See the HTML report from running axe-core 4.14.0 over this page.

Every example is live in the page, so you can run the axe extension straight over it. The expected results were checked by running axe-core 4.14.1 over this page. Look in both the axe issues list and the needs review list.

Skipped by axe on purpose

These pass, because axe relaxes the rule where the missing attribute isn't needed.

B1 A slider with aria-valuetext

aria-valuetext gives the value as text, so aria-valuenow isn't needed.

<div role="slider" tabindex="0" aria-label="Spice level" aria-valuetext="Medium"></div>

Expected result: pass (valid)

B2 A separator that can't receive focus

A plain dividing line doesn't have a value. Compare with A7.

<div role="separator"></div>

Expected result: pass (valid)

B3 A closed combobox without aria-controls

ARIA 1.2 requires aria-controls, but axe doesn't while the combobox is closed, because the popup may not exist yet.

<input type="text" role="combobox" aria-label="Country" aria-expanded="false">

Expected result: pass (valid)

B4 A native checkbox with role="switch"

The native checkbox already provides the checked state.

<label><input type="checkbox" role="switch"> Dark mode</label>

Expected result: pass (valid)

B5 A native heading with role="heading"

The <h2> already provides the level.

Contact

<h2 role="heading">Contact</h2>

Expected result: pass (valid)

Not tested at all

Changes after interaction

Axe only sees the page as it is when you run it. These pass on page load. Activate each button, then run axe again.

F1 A checkbox that loses its state

When unticked, the script removes aria-checked instead of setting it to false.

Keep me signed in
<div role="checkbox" tabindex="0" id="f1-box" aria-checked="true">Keep me signed in</div>

On load: pass. After clicking: fail

After clicking, the message key is none, so it routes to NEW-43.
