Setting up Node.js

What this tutorial is about

Running axe-core in the browser console only needed Chrome. The next tutorials in this series run axe-core outside the browser, so you'll need a few tools installed first.

This tutorial walks you through it, step by step, on a Mac or on Windows. Where the steps are different, you'll see a Mac version and a Windows version. You only need to do this once.

By the end, you'll have installed Node.js, created a project folder, installed the accessibility tools, and run your first check.

Before you start

You'll need:

  • a Mac or a Windows computer
  • an internet connection
  • permission to install software on your computer. On some work computers, this needs approval from your IT team.
  • about 20 to 30 minutes.

Check your computer

Step 1. Open your command line app

You'll be typing commands into a command line app. It lets you control your computer by typing instead of clicking. It looks a bit plain, but you only need a handful of commands, and each one is explained as you go.

  • Mac: the app is called Terminal. To open it, press Command + Space, type Terminal, then press Return.
  • Windows: the app is called Command Prompt. To open it, press the Windows key, type Command Prompt, then press Enter.

How to use the commands in this tutorial:

  • Copy each command exactly as it's shown, paste it into your command line app, then press Return (Mac) or Enter (Windows). To paste, press Command + V on Mac. On Windows, press Ctrl + V or right-click inside the window.
  • Do one command at a time, and wait for it to finish before typing the next one. You'll know it's finished when you see a blinking cursor on a new line. On Windows, the new line starts with something like C:\Users\yourname>.
  • If you see words like warn or deprecated in the output, don't worry. These are normal and you can ignore them.

Watch out for:

  • On Windows, use Command Prompt, not PowerShell. PowerShell looks similar, but it often blocks the tools in this tutorial with an error saying "running scripts is disabled on this system". Command Prompt doesn't have that problem.
  • To check you're in Command Prompt, look at the line where you type. If it starts with PS, like PS C:\Users\yourname>, you're in PowerShell. Close it and open Command Prompt instead.

Step 2. Check you have Node.js

Node.js is a program that lets your computer run JavaScript outside a web browser. The accessibility tools in this series are written in JavaScript, so they need Node.js to work.

Type:

node -v

(The -v is short for "version".)

You should see a version number that starts with the letter v, like v22.12.0.

What the number means: the first number is the main version. You need version 22.12 or higher, because older versions are missing features these tools rely on.

  • v22.12.0, or anything starting with v23, v24 or higher: you're good to go.
  • v20..., v18... or anything lower: too old, so follow the steps below.

If you see an error, or your version is too old: the error says "command not found" on a Mac, or "'node' is not recognized as an internal or external command" on Windows.

  1. Go to nodejs.org.
  2. Download the version marked LTS, which stands for "Long Term Support". It's the stable version most people should use. On Windows, choose the Windows Installer (.msi).
  3. Open the file you downloaded and follow the steps in the installer.
    • Mac: your Mac may ask for your password. That's normal.
    • Windows: you can accept the default settings on each screen, with one exception. When you reach a screen called Tools for Native Modules, leave the box unticked. Ticking it installs a lot of extra software you don't need. Windows may also ask "Do you want to allow this app to make changes to your device?" That's normal. Click Yes.
  4. Close your command line app completely, then open it again.
    • Mac: press Command + Q to quit Terminal.
    • Windows: click the X in the corner of Command Prompt, or type exit and press Enter.
  5. Type node -v again to check it worked.

Step 3. Check you have npm

npm stands for "Node Package Manager". It downloads and installs extra software, called packages, that other people have written. You'll use it to install the accessibility tools.

npm comes with Node.js, so if you have Node.js, you have npm too.

Type:

npm -v

You should see a version number, such as 10.9.2. Any number means npm is working.

If you see an error saying "command not found" (Mac) or "'npm' is not recognized" (Windows), install (or reinstall) Node.js using the steps in step 2. npm comes with it.

Step 4. Check you have Google Chrome

The accessibility tools open Google Chrome behind the scenes to check your pages, so you need Chrome installed.

  • Mac: if you don't have Chrome, download it from google.com/chrome.
  • Windows: Windows only comes with Microsoft Edge, not Chrome. So unless you've installed Chrome yourself, download it from google.com/chrome.

Step 5. Show file name extensions (Windows only)

Mac: you can skip this step.

Windows: a file name extension is the part at the end of a file name after the dot, like .js in check.js. It tells your computer what kind of file it is.

Windows hides extensions by default. That means a file actually called check.js.txt can look like check.js, and the tools won't work with it. Turning extensions on lets you see the real name.

On Windows 11:

  1. Open File Explorer (press Windows key + E).
  2. Click View in the menu at the top.
  3. Point to Show, then click File name extensions so it has a tick next to it.

On Windows 10:

  1. Open File Explorer (press Windows key + E).
  2. Click the View tab at the top.
  3. Tick the File name extensions box.

Watch out for:

  • A proper code editor, such as VS Code, is the most reliable way to create and edit code files, on both Mac and Windows.
  • On Mac, avoid TextEdit. It can save files as formatted text instead of plain code.
  • On Windows, Notepad also works, as long as the file already exists with the right name, which is how these tutorials use it. The thing to avoid is Save As in Notepad. That's when it adds .txt to the end of the name, unless you change Save as type to All files first.

Set up your project

Step 6. Create a project folder

You'll keep everything for this series in one folder. Type these commands one at a time.

Mac:

cd Documents

cd stands for "change directory". (Directory is another word for folder.) This moves you into your Documents folder.

Windows:

cd %USERPROFILE%

cd stands for "change directory". (Directory is another word for folder.) %USERPROFILE% is a shortcut that means "my user folder", which is C:\Users\ followed by your user name. This moves you into that folder.

Then, on both Mac and Windows:

mkdir axe-learning

mkdir stands for "make directory". This creates a new folder called axe-learning.

cd axe-learning

This moves you into the new folder.

To check it worked:

  • Mac: type pwd and press Return. pwd stands for "print working directory", which is a fancy way of saying "show me where I am". You should see something ending in /Documents/axe-learning.
  • Windows: type cd on its own and press Enter. This shows you which folder you're in. You should see something like C:\Users\yourname\axe-learning.

Important: from now on, every command should be typed while you're inside this folder. If you close your command line app and come back later, you'll need to move back into the folder first:

  • Mac: type cd Documents/axe-learning and press Return.
  • Windows: type cd %USERPROFILE%\axe-learning and press Enter.

Watch out for:

  • On Windows, don't put the folder in Documents. On many Windows computers, especially new ones, the Documents folder is synced to OneDrive. The tools you're about to install contain thousands of small files, and OneDrive will try to upload every one of them, which is slow and messy. Your user folder isn't synced, so it's a better place.

Step 7. Turn the folder into a project

Type:

npm init -y

This turns your folder into a project, which means npm can install tools into it. The -y stands for "yes", and accepts all the default settings for you, so you won't be asked any questions.

You'll see some text appear on screen. That's npm showing you what it created, a file called package.json. Think of this file as the project's notebook: it keeps a list of the tools you install.

To check it worked, list the files in your folder:

  • Mac: type ls and press Return. ls stands for "list".
  • Windows: type dir and press Enter. dir is short for "directory".

You should see package.json in the list.

Step 8. Install the accessibility tools

Type:

npm install @axe-core/cli playwright @axe-core/playwright

This installs three tools in one go. It may take a minute.

  • @axe-core/cli checks a web page for accessibility problems when you type one command. "CLI" stands for "command line interface", which just means a tool you use by typing commands rather than clicking buttons.
  • playwright controls a web browser automatically. It can open pages, click buttons and fill in forms, just like a person would.
  • @axe-core/playwright lets the accessibility checker run while Playwright is in control of the browser. This is useful for pages that need you to log in or click through steps before you check them.

You'll notice a new folder called node_modules appears in your project folder. That's where npm stores the tools it installed. You never need to open it or change anything in it.

To check it worked, type:

npm ls

You should see the three tools listed, each with a version number.

Step 9. Download Playwright's browser

Playwright uses its own copy of a browser, separate from the Chrome you normally use. Type:

npx playwright install chromium

Chromium is the free, open-source browser that Google Chrome is built on. This download may take a minute or two.

You'll see progress bars while it downloads. It's finished when the blinking cursor comes back on a new line.

Connect to Chrome

Step 10. Find your Chrome version

The axe command line tool uses a helper program called ChromeDriver to control Chrome. Each copy of ChromeDriver only works with one main version of Chrome, so you need to install one that matches yours. First, find out which version of Chrome you have.

  1. Open Google Chrome.
  2. Click in the address bar, type chrome://version, then press Return (Mac) or Enter (Windows).
  3. Look at the first line. It says something like Google Chrome 155.0.8059.85.

The first number, in this case 155, is the main version. Make a note of it.

Step 11. Install a matching ChromeDriver

Type this, replacing 155 with your main version number:

npm install chromedriver@155

This downloads the ChromeDriver that matches your Chrome, and puts it in your project folder.

To check it worked, type:

npm ls

You should now see four tools listed, including chromedriver, with a version number starting with your Chrome version.

Step 12. Run your first check

Type the version for your computer:

Mac:

npx axe https://example.com --chromedriver-path "node_modules/chromedriver/lib/chromedriver/chromedriver"

Windows:

npx axe https://example.com --chromedriver-path "node_modules\chromedriver\lib\chromedriver\chromedriver.exe"

npx comes with npm. It runs a tool you've installed in your project. Here it runs axe, which:

  1. opens the page in an invisible copy of Chrome
  2. checks it for common accessibility problems
  3. lists any problems it finds.

The --chromedriver-path part tells axe to use the ChromeDriver you just installed. You'll include it every time you run a check.

It can take a few seconds, so be patient. When it's done, you'll see a list of any problems it found, followed by a line saying how many it found in total.

To check a different page, replace https://example.com with that page's address.

Watch out for:

  • An error mentioning "session not created" or "This version of ChromeDriver only supports Chrome version" means ChromeDriver and Chrome don't match. Check the version number you used in step 11. The error also shows your Chrome version, in a line like Current browser version is 155.0.8059.85.
  • The error message suggests a tool called browser-driver-manager. You can ignore that. Installing ChromeDriver with npm, as in step 11, is simpler.
  • Chrome updates itself every few weeks. When it does, this error will come back. Repeat steps 10 and 11 with the new version number.
