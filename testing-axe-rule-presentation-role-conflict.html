Testing the axe rule presentation-role-conflict

Test cases for the axe-core rule presentation-role-conflict (axe-core 4.14). role="none" and role="presentation" tell browsers to ignore an element's meaning, so a <ul> stops being a list. But browsers won't ignore an element that:

  • can receive focus, or
  • has a global ARIA attribute, such as aria-label or aria-describedby.

When that happens, the browser keeps the element's own role, and role="none" does nothing. The rule flags these conflicts. It's a best practice rule, so it isn't tied to a WCAG success criterion.

The rule checks three things: img with alt="", and elements whose role attribute is exactly none or exactly presentation. It also skips elements that have no role of their own to keep, such as a <div> or <span>.

Two things to know before reading the results:

  • The messages read backwards. Axe reports "Element does not have global ARIA attribute" on an element that does have one, and "Element is not focusable" on one that is focusable. Both are the wrong wording for the result, so ignore the message and look at the element.
  • The attribute names are in data, not data.values. For has-global-aria-attribute, axe's JSON has "data": ["aria-label"]. NEW-35's assembly notes say data.values, which would come out empty.

Each case shows the check that found the conflict and how NEW-35 would fill its [conflict] placeholder. The accessibility tree notes come from Chrome.

axe-core results: See the HTML report from running axe-core 4.14.0 over this page.

Global ARIA attribute

These fail through has-global-aria-attribute. In each one, Chrome ignores role="none" and keeps the element's own role.

A1 List with role="none" and aria-label

Chrome shows a list named "Styles".

  • Bold
  • Italic
<ul role="none" aria-label="Styles">
  <li>Bold</li>
  <li>Italic</li>
</ul>

Expected result: fail

aria-prohibited-attr also asks for review, and its message gives the game away: "not well supported with role list".

Template routing: Check: has-global-aria-attribute, message key: none, data: ["aria-label"]. Routes to: NEW-35, with [conflict] as "has the aria-label attribute".

Changes after interaction

Axe only sees the page as it is when you run it. These pass on page load. Activate each button, then run axe again.

G1 Description added to a layout table

On load, the layout table is fine. The button adds aria-describedby, which turns it back into a table.

Total$40

Includes delivery.

<button type="button" id="g1-button">Add description</button>
<table role="presentation" id="g1-table">
  <tr><td>Total</td><td>$40</td></tr>
</table>
<p id="g1-note">Includes delivery.</p>

On load: pass. After clicking: fail

After clicking, it routes to NEW-35 with data ["aria-describedby"].
