Testing the axe rule aria-command-name

Test cases for the axe-core rule aria-command-name (axe-core 4.14). The rule checks that elements with role="button", role="link" or role="menuitem" have an accessible name.

The element passes if any one of these checks passes:

  • has-visible-text: it has text content that is exposed to screen readers. Despite the name, visually hidden text counts.
  • aria-label: it has a non-empty aria-label.
  • aria-labelledby: it points to an element that has text.
  • non-empty-title: it has a non-empty title.

Native elements like <button> and <a href> are left to other rules (button-name and link-name), even when they have one of these roles.

axe-core results: See the HTML report from running axe-core 4.14.0 over this page.

Every example is live in the page, so you can run the axe extension straight over it. The expected results were checked by running axe-core 4.14.1 over this page. Look in both the axe issues list and the needs review list.

Not tested at all

The rule only looks for an exact role="button", role="link" or role="menuitem". Anything else slips past, and no other axe rule picks these up.

C1 Uppercase role

Browsers generally treat this as a button, but axe's selector doesn't match it.

<div role="Button" tabindex="0"></div>

Expected result: passes, but it's broken (check manually)

C2 Trailing space in the role

<div role="button " tabindex="0"></div>

Expected result: passes, but it's broken (check manually)

C3 Fallback role list

Browsers use the first role they recognise, which is button.

<div role="button link" tabindex="0"></div>

Expected result: passes, but it's broken (check manually)

Flagged by a different rule instead

This rule doesn't flag these, but another one does. Worth knowing when you're reading a report.

D1 Empty link with role="button"

An <a href> is handled by link-name, even though it says it's a button.

<a href="#d1" role="button"></a>

Expected result: flagged by link-name instead

D2 Empty native button with role="menuitem"

A <button> is handled by button-name.

<div role="menu" aria-label="View">
  <button type="button" role="menuitem"></button>
</div>

Expected result: flagged by button-name instead

D3 Empty menuitemcheckbox

menuitemcheckbox and menuitemradio aren't covered by this rule.

<div role="menu" aria-label="Format">
  <div role="menuitemcheckbox" tabindex="-1" aria-checked="false"></div>
</div>

Expected result: flagged by aria-toggle-field-name instead

D4 Focusable button hidden with aria-hidden

Axe skips aria-hidden elements, so this rule never sees it. But you can still tab to it.

<div role="button" tabindex="0" aria-hidden="true"></div>

Expected result: flagged by aria-hidden-focus instead

D5 Name doesn't match the visible text

It has a name, so this rule passes. But a voice control user saying "click Send" won't hit it.

Send
<div role="button" tabindex="0" aria-label="Submit">Send</div>

Expected result: flagged by label-content-name-mismatch instead

Changes after interaction

Axe only sees the page as it is when you run it. These pass on page load. Activate each button, then run axe again.

F1 Play button loses its name

When pressed, the script is meant to change the label to "Pause", but it sets it to an empty string.

<div role="button" tabindex="0" id="f1-button" aria-label="Play">
  <svg width="16" height="16" viewBox="0 0 16 16" aria-hidden="true"><path d="M4 2 L13 8 L4 14 Z" fill="currentColor"/></svg>
</div>

On load: pass. After pressing: fail

F2 Menu with an empty item, hidden until opened

Axe doesn't test hidden content. The empty menu item is only found once the menu is open.

Rename
<button type="button" id="f2-button" aria-expanded="false" aria-controls="f2-menu">Options</button>
<div role="menu" id="f2-menu" aria-label="Options" hidden>
  <div role="menuitem" tabindex="-1">Rename</div>
  <div role="menuitem" tabindex="-1"></div>
</div>

On load: pass. After opening: fail
