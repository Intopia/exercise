Running axe-core in the browser console

axe-core is a free, open-source accessibility testing engine. It's the engine inside tools like the axe DevTools browser extension.

In this article, you'll run axe-core directly from Chrome's browser console. There's nothing to install, and no extension needed.

The basic idea behind axe tools:

  1. Load a page.
  2. Run an accessibility test.
  3. Do something with the results.

Every axe tool, from browser extensions to automated test suites, follows these same three basic steps.

Tools like browser extensions can seem a bit magical. But under the surface, axe-core just produces a set of results. How you look at those results, filter them, report on them and act on them is up to you.

What you'll learn

This article will help you understand how axe-core works by running it directly in the browser console. You'll see how axe-core produces accessibility test results and how tools like axe DevTools build on this functionality to make testing easier.

Most teams don't use the browser console for everyday accessibility testing. However, it's a useful way to understand how axe-core works before moving on to running tests from the command line.

Steps at a glance

  1. Open the test page: a page with seven intentional accessibility issues.
  2. Open the console: where you'll run JavaScript in the browser.
  3. Load axe-core into the page: add the axe-core script to the page.
  4. Check axe has loaded: confirm the version number.
  5. Run axe: run the accessibility checks and store the results.
  6. Look inside the results: explore the four groups of results.
  7. Count the failed rules: see how many rules found violations.
  8. Show the violations as a table: view each rule, its impact and the number of affected elements.
  9. Filter to critical and serious: focus on the most severe issues.
  10. See which elements failed: identify the elements with accessibility issues.
  11. Highlight the failing elements: outline the affected elements on the page.
  12. Copy the results: copy the full results as JSON.
  13. Open a full report in a new tab: view a readable report in a separate browser tab.
  14. Try the fixed page: see what a page with no reported violations looks like.

You only need Google Chrome. There's nothing to install.

1. Open the test page

Open the axe test page in Chrome, since its console is the easiest to work with.

The page has 7 deliberately planted accessibility errors. The table below explains each issue, so you can compare them with axe-core's results.

Error What's wrong
1 The page doesn't say what language it's in
2 A heading jumps from level 1 to level 3
3 An image has no alt text
4 A text box has no label
5 A button has no text
6 A link has no text
7 Some grey text has low contrast

You should see a heading, a placeholder image, an empty text box, an empty button and an empty link, and some faint grey text. The button and link have red borders, so you can see where they are, even though they have no text.

2. Open the console

Open Chrome's developer tools and go to the Console tab. This is where you'll type JavaScript straight into the page.

  • Mac: Command + Option + J
  • Windows: Ctrl + Shift + J

Watch out for:

  • Click on the web page first. Otherwise the shortcut may go to a different app.
  • If the shortcut doesn't work, right-click anywhere on the page, choose Inspect, then click the Console tab.

3. Load axe-core into the page

Paste this code into the console and press Enter. It adds the axe-core script to the page. It's the same as writing a <script> element into the HTML, just done live.

const script = document.createElement('script');
script.src = 'https://cdn.jsdelivr.net/npm/axe-core@4.14.0/axe.min.js';
document.head.appendChild(script);

In plain terms:

  1. Make a new <script> element.
  2. Point it at the axe-core file, which is hosted online.
  3. Add it to the page, so the browser downloads and runs it.

Watch out for:

  • Chrome may block your first paste. If it does, type allow pasting, press Enter, then paste again.
  • The address includes a version number (axe-core@4.14.0), so you get the same results as this article, even after newer versions of axe-core come out.

4. Check axe has loaded

Type this and press Enter:

axe.version

You should see '4.14.0'. That means axe is now running inside the page, waiting to be told what to do.

Watch out for:

  • If you see "axe is not defined", the file may still be downloading. Wait a couple of seconds and try again.

5. Run axe

Paste this and press Enter:

const results = await axe.run();

In plain terms: "run axe on the whole page, wait for it to finish, and store everything it found in a box called results."

Nothing will happen yet. axe has run, but the results are sitting in the box, waiting for you to look at them. The console will just show undefined, which means the line ran and had nothing to show.

6. Look inside the results

Type this and press Enter:

results

Click the small triangle at the start of the line to expand it. Near the bottom, you'll find four groups, each with a count in brackets:

  • violations: rules that failed (7)
  • passes: rules that passed
  • incomplete: rules axe couldn't decide on, so a human needs to check
  • inapplicable: rules with nothing to check on this page, such as table rules on a page with no tables

This four-way split is the heart of how axe works. It never says a page is accessible, only what it could and couldn't confirm.

Watch out for:

  • The groups are listed in alphabetical order, mixed in with other details such as the page address and the time of the test.
  • The rules under inapplicable look like errors, because each one is described as a requirement. They're not errors, just rules that didn't apply.

7. Count the failed rules

Type this and press Enter:

results.violations.length

In plain terms: "from results, take the violations bucket, and tell me its length", which means how many items are in it. Each dot steps one level further into the box.

You should see 7, one for each planted error.

Watch out for:

  • The count is the number of rules that failed, not individual problems. Three images with no alt text would still count as one failed rule.

8. Show the violations as a table

Paste this and press Enter:

console.table(results.violations.map(v => ({
  rule: v.id,
  impact: v.impact,
  instances: v.nodes.length,
  help: v.help
})));

In plain terms: "for each violation, pull out four things (the rule's name, how severe it is, how many elements failed and a short description), then show them as a table."

You should see a table with 7 rows: 3 critical, 3 serious and 1 moderate.

Watch out for:

  • axe lists rules alphabetically, not by severity or by where they appear on the page.

9. Filter to critical and serious

Paste this and press Enter:

results.violations
  .filter(v => v.impact === 'critical' || v.impact === 'serious')
  .forEach(v => console.log(v.impact, v.id));

In plain terms: "keep only the violations that are critical or serious, then print each one on its own line."

You should see 6 lines. heading-order is gone, because it's moderate.

axe itself always reports everything. Every tool that lets you filter by severity is doing exactly this, afterwards, on the results.

Watch out for:

  • axe has four impact levels: critical, serious, moderate and minor. There's no "high".

10. See which elements failed

Paste this and press Enter:

results.violations.forEach(v =>
  v.nodes.forEach(n => console.log(v.id, '|', n.target.join(' '), '|', n.html))
);

In plain terms: "for each violation, go through every element that failed it, and print the rule's name, the element's CSS selector (the target) and its HTML."

You should see 7 lines, each showing the problem code from your test page, such as <img src="https://placehold.co/200x200"> on the image-alt line. This answers the "where on the page?" question.

Watch out for:

  • On this small page, each target is just an element name like img. On a real site, it would be a longer selector that points to one exact element.

11. Highlight the failing elements

See the problems on the page itself, not just in the console. Paste this and press Enter:

results.violations.forEach(v =>
  v.nodes.forEach(n => {
    const el = document.querySelector(n.target[0]);
    if (el) el.style.outline = '4px dashed red';
  })
);

In plain terms: "for each element that failed, find it on the page using its CSS selector (the target), and draw a thick, dashed red outline around it."

You should see dashed red outlines appear around the 7 problem elements: the heading, image, text box, button, link, faint text, and the whole page (for the missing lang).

Watch out for:

  • The outlines are temporary. Reload the page to remove them.
  • Only change how the elements look, not what they are. For example, adding a title to label each element would give the empty button an accessible name, and axe would then pass it. A highlight shouldn't change the accessibility of what it's highlighting.

12. Copy the results

Chrome's console has a built-in copy() command. Type this and press Enter:

copy(results)

In plain terms: "copy everything in results to the clipboard."

The console will just show undefined. Now paste (Command + V on Mac, Ctrl + V on Windows) into a text editor. You'll see the full results as JSON.

This is the same data that other axe tools work with. The axe command line tool, for example, saves exactly this to a file. Both come from the same axe.run().

Watch out for:

  • copy() only works when you type it into the console. It won't work inside a web page's own code or a bookmarklet.
  • The results can be long. Paste them into a code editor rather than a chat or email.

13. Open a full report in a new tab

Turn the results into a readable report, and open it in a new browser tab. Paste this and press Enter:

{
  const escape = s => String(s ?? '')
    .replace(/&/g, '&amp;')
    .replace(/</g, '&lt;')
    .replace(/>/g, '&gt;')
    .replace(/"/g, '&quot;');

  const order = { critical: 0, serious: 1, moderate: 2, minor: 3 };
  const violations = [...results.violations].sort((a, b) => order[a.impact] - order[b.impact]);

  const sections = violations.map(v => `
    <section>
      <h2>${escape(v.help)}</h2>
      <p><strong>Impact:</strong> ${escape(v.impact)}. <strong>Rule:</strong> <code>${escape(v.id)}</code></p>
      <p>${escape(v.description)}</p>
      <h3>Failing elements</h3>
      <ul>
        ${v.nodes.map(n => `
        <li>
          <pre><code>${escape(n.html)}</code></pre>
          <pre>${escape(n.failureSummary)}</pre>
        </li>`).join('')}
      </ul>
      <p><a href="${escape(v.helpUrl)}">Learn more about ${escape(v.id)}</a></p>
    </section>`).join('');

  const html = `<!DOCTYPE html>
<html lang="en">
<head>
<meta charset="utf-8">
<title>axe report</title>
<style>
  body { font-family: system-ui, sans-serif; line-height: 1.5; max-width: 60rem; margin: 2rem auto; padding: 0 1rem; }
  section { border-top: 2px solid #ccc; margin-top: 2rem; }
  pre { background: #f4f4f4; padding: 0.75rem; white-space: pre-wrap; }
</style>
</head>
<body>
<main>
<h1>axe report</h1>
<p>Page: <code>${escape(results.url)}</code></p>
<p>${results.violations.length} violations, ${results.passes.length} passes, ${results.incomplete.length} need review.</p>
${sections}
</main>
</body>
</html>`;

  window.open(URL.createObjectURL(new Blob([html], { type: 'text/html' })));
}

In plain terms:

  1. escape makes sure any HTML in the results shows up as text, not as real buttons and links.
  2. The violations are sorted from critical to minor.
  3. Each violation becomes a section, with its description, impact, failing elements, "how to fix" text and a help link.
  4. The sections are wrapped in a simple web page.
  5. window.open opens that page in a new tab.

You should see a new tab called "axe report", listing all 7 violations, with the critical ones first.

Watch out for:

  • If nothing opens, Chrome may have blocked the new tab as a pop-up. Look for a blocked pop-up icon at the right of the address bar, and choose to allow pop-ups for this page.
  • The report only exists in the browser. To keep it, save the page (Command + S on Mac, Ctrl + S on Windows) while you're on the report tab.
  • The curly brackets around the code mean you can paste it again without causing an error.

14. Try the fixed page

There's also a fixed version of the test page, with all 7 errors fixed.

  1. Open the fixed page in Chrome.
  2. Open the console.
  3. Paste the quick start from step 14, and press Enter.
  4. Type this and press Enter:
results.violations.length

You should see 0. Now try:

results.passes.length

You should see more passes than on the broken page, because the fixed elements now pass the rules they failed before.

Watch out for:

  • 0 violations doesn't mean the page is accessible. axe only checks what a computer can test. A person still needs to check things like whether alt text makes sense, and whether everything works with a keyboard.
  • The fixed page marks its image as decorative, with alt="". On a real page, an image that carries meaning needs alt text that describes it.

Quick start: the two essentials

Every step after step 5 uses results. And results only exists once two things have happened in the page you're on:

  1. Load axe into the page (step 3)
  2. Run axe and store the results (step 5)

Everything else is optional, and you can do it in any order: look inside the results, count them, show a table, filter by severity, see which elements failed, highlight them, copy them or open a full report.

If you reload the page, or move to a different page, both essentials are wiped. So you need to do them again before any of the other steps will work.

Here's a single paste that does both. Reload the page to start fresh, then paste this and press Enter:

const script = document.createElement('script');
script.src = 'https://cdn.jsdelivr.net/npm/axe-core@4.14.0/axe.min.js';
const loaded = new Promise(resolve => script.onload = resolve);
document.head.appendChild(script);
await loaded;
const results = await axe.run();

In plain terms:

  1. Make a <script> element, and point it at the axe-core file.
  2. Get ready to notice when it has finished loading.
  3. Add it to the page, so the browser downloads it.
  4. Wait until it has loaded.
  5. Run axe, and store the results in results.

The console will show undefined when it's done. Now paste any of the steps from 6 to 13, in whatever order you like.

Watch out for:

  • You can't just paste the lines from steps 3 and 5 together. The page needs a moment to download axe, so the axe.run() line runs too early and fails with "axe is not defined". The loaded line is what makes it wait.
  • This works on many web pages, not just your test page. But some sites, such as GitHub and most banking sites, block scripts from outside addresses. On those, you'll see a large red error in the console, starting with something like "Refused to load the script", and mentioning a "Content Security Policy". That's the site protecting itself, not something you did wrong. Practise on your test page or simple sites first.
