Testing the axe rule aria-valid-attr

Test cases for the axe-core rule aria-valid-attr (axe-core 4.14). The rule checks that every attribute starting with aria- is a real ARIA attribute. Browsers ignore attributes they don't recognise, so a misspelled attribute does nothing at all.

This rule only checks the attribute name. Whether the value is valid is checked by aria-valid-attr-value, and whether the attribute suits the role is checked by aria-allowed-attr.

Each case also shows the axe message key and which Intopia issue template the result would go to under the current assembly rules. Results on this page were checked in Chrome.

axe-core results: See the HTML report from running axe-core 4.14.0 over this page.

Every example is live in the page, so you can run the axe extension straight over it. The expected results were checked by running axe-core 4.14.1 over this page. Look in both the axe issues list and the needs review list.

Misspelled attributes

These fail with "Invalid ARIA attribute name". Each one is ignored by browsers, so the name, description or state it was meant to give is missing.

A1 aria-labeledby (one l)

The most common misspelling. The correct name is aria-labelledby.

Save changes 
<span id="a1-label">Save changes</span>
<button type="button" aria-labeledby="a1-label">Save</button>

Expected result: fail

Template routing: Message key: none. Routes to: NEW-26.

A2 aria-lable

<button type="button" aria-lable="Close">X</button>

Expected result: fail

Template routing: Message key: none. Routes to: NEW-26.

A3 aria-describeby

The correct name is aria-describedby.

At least 12 characters.

<label for="a3-input">Password</label>
<input type="password" id="a3-input" aria-describeby="a3-hint">
<p id="a3-hint">At least 12 characters.</p>

Expected result: fail

Template routing: Message key: none. Routes to: NEW-26.

A4 aria-labelled-by

An extra hyphen.

Delivery address
12 Smith Street
<span id="a4-label">Delivery address</span>
<div role="region" aria-labelled-by="a4-label">12 Smith Street</div>

Expected result: fail

Template routing: Message key: none. Routes to: NEW-26.

A5 aria-relevent

The correct name is aria-relevant.

Chat messages.
<div aria-live="polite" aria-relevent="additions">Chat messages.</div>

Expected result: fail

Template routing: Message key: none. Routes to: NEW-26.

A6 aria- with nothing after it

Promotions
<div aria-="true">Promotions</div>

Expected result: fail

Template routing: Message key: none. Routes to: NEW-26.

Attributes that don't exist

Some look reasonable, but aren't part of ARIA.

B1 aria-role

Use the role attribute instead.

Continue
<div aria-role="button" tabindex="0">Continue</div>

Expected result: fail

Template routing: Message key: none. Routes to: NEW-26.

B2 aria-tooltip

Help 
<span aria-tooltip="Opens in a new tab">Help</span>

Expected result: fail

Template routing: Message key: none. Routes to: NEW-26.

B3 aria-mandatory

The real attribute is aria-required.

<label for="b3-input">Email</label>
<input type="email" id="b3-input" aria-mandatory="true">

Expected result: fail

Template routing: Message key: none. Routes to: NEW-26.

B4 aria-toggled

The real attribute is aria-pressed.

<button type="button" aria-toggled="false">Bold</button>

Expected result: fail

Template routing: Message key: none. Routes to: NEW-26.

B5 A misspelling next to the correct attribute

The correct aria-labelledby still works. Only the misspelled one is ignored, but the element still fails.

Print receipt 
<span id="b5-label">Print receipt</span>
<button type="button" aria-labelledby="b5-label" aria-labeledby="b5-label">Print</button>

Expected result: fail

Template routing: Message key: none. Routes to: NEW-26.

Not tested at all

The rule only looks at attributes that start with aria-. These slip past, and nothing in axe flags them.

C1 An underscore instead of a hyphen

<button type="button" aria_label="Close">X</button>

Expected result: passes, but it's broken (check manually)

Browsers ignore it, so the button's name is just "X".

Template routing: No result, so nothing to route.

C2 No hyphen at all

<button type="button" arialabel="Close">X</button>

Expected result: passes, but it's broken (check manually)

Template routing: No result, so nothing to route.

Flagged by a different rule instead

D1 A deprecated attribute

aria-grabbed is a real attribute name, so this rule passes it. It was deprecated in ARIA 1.1.

Drag me
<div aria-grabbed="false">Drag me</div>

Expected result: flagged by aria-allowed-attr instead

Template routing: aria-allowed-attr, check aria-no-deprecated-attr, needs review. Routes to: NEW-40.

Ways to pass

Control cases.

E1 Correctly spelled attributes

Search the shop

Search by product name.

<span id="e1-label">Search the shop</span>
<input type="search" aria-labelledby="e1-label" aria-describedby="e1-hint">
<p id="e1-hint">Search by product name.</p>

Expected result: pass (valid)

E2 An uppercase attribute name

HTML attribute names aren't case sensitive, so ARIA-LABEL is read as aria-label.

Free delivery this week.
<div role="region" ARIA-LABEL="Special offers">Free delivery this week.</div>

Expected result: pass (valid)

E3 Newer attributes

aria-description and aria-braillelabel are newer, but axe knows them.

<button type="button" aria-description="Removes the item from your cart" aria-braillelabel="del">Delete</button>

Expected result: pass (valid)

E4 A data attribute

data-aria-label isn't an ARIA attribute, it's a custom data attribute, so it's fine.

<button type="button" data-aria-label="close-button">Close</button>

Expected result: pass (valid)

Changes after interaction

Axe only sees the page as it is when you run it. These pass on page load. Activate each button, then run axe again.

F1 A script writes a misspelled attribute

The button starts correct. When pressed, the script sets aria-expaned instead of aria-expanded, so the state never changes for screen reader users.

Price, size and colour.
<button type="button" id="f1-button" aria-expanded="false" aria-controls="f1-panel">Show filters</button>
<div id="f1-panel" hidden>Price, size and colour.</div>

On load: pass. After pressing: fail

After pressing, the message key is none, so it routes to NEW-26.
