Testing aria-pressed

aria-pressed indicates the current "pressed" state of a toggle button. It supports three values, true, false, and mixed. It is intended for use on a real <button> element, or an element with role="button".

This page uses a single live example to demonstrate all three states, and to demonstrate why mixed exists in the first place: it is a computed consequence of related controls disagreeing, not a state a button starts in or that a user reaches directly.

Example: Mute all

The "Mute all" button controls three individual track buttons. Its own aria-pressed state is not set directly, it is recalculated every time a track button changes:

  • all three tracks unmuted → aria-pressed="false"
  • all three tracks muted → aria-pressed="true"
  • a mix of muted and unmuted tracks → aria-pressed="mixed"

Pressing "Mute all" while it is false or mixed mutes every track and sets it to true. Pressing it while it is true unmutes every track and sets it back to false.

There is no aria-live region on this page. State changes are only announced when focus lands on, or returns to, a button whose aria-pressed has changed since it was last focused. This is deliberate: it is the honest, default behaviour of aria-pressed without any extra announcement mechanism layered on top.

Try this:

  1. Tab to "Mute all". It should announce as not pressed.
  2. Tab to "Mute track 2" and activate it. It should announce as pressed.
  3. Shift-tab back to "Mute all". It should now announce as mixed, not not-pressed, because one of three tracks is muted.
  4. Mute the remaining two tracks individually. "Mute all" should now announce as pressed once all three agree.
  5. Activate "Mute all" directly from a mixed or unpressed state. All three tracks should mute and "Mute all" should announce as pressed.
  6. Activate "Mute all" again while it is pressed. All three tracks should unmute and "Mute all" should return to not pressed.

Expected result: worth confirming directly rather than assuming, whether mixed is announced distinctly from true or false (for example, as "mixed" or "partially pressed" rather than "pressed") has historically varied across screen reader and browser combinations, and is worth checking against your standard test set.

HTML markup 
<button id="mute-all" aria-pressed="false">
  Mute all
</button>
<ul>
  <li><button id="track-1" aria-pressed="false">Mute track 1</button></li>
  <li><button id="track-2" aria-pressed="false">Mute track 2</button></li>
  <li><button id="track-3" aria-pressed="false">Mute track 3</button></li>
</ul>
JavaScript 
const muteAll = document.getElementById('mute-all');
const trackButtons = Array.from(document.querySelectorAll('.track-button'));

function updateMuteAll() {
  const states = trackButtons.map(btn => btn.getAttribute('aria-pressed'));
  const allTrue = states.every(state => state === 'true');
  const allFalse = states.every(state => state === 'false');

  if (allTrue) {
    muteAll.setAttribute('aria-pressed', 'true');
  } else if (allFalse) {
    muteAll.setAttribute('aria-pressed', 'false');
  } else {
    muteAll.setAttribute('aria-pressed', 'mixed');
  }
}

trackButtons.forEach(btn => {
  btn.addEventListener('click', () => {
    const isPressed = btn.getAttribute('aria-pressed') === 'true';
    btn.setAttribute('aria-pressed', String(!isPressed));
    updateMuteAll();
  });
});

muteAll.addEventListener('click', () => {
  const currentState = muteAll.getAttribute('aria-pressed');
  // true resolves to false (unmute all)
  // false or mixed both resolve to true (mute all)
  const nextState = currentState === 'true' ? 'false' : 'true';

  trackButtons.forEach(btn => btn.setAttribute('aria-pressed', nextState));
  muteAll.setAttribute('aria-pressed', nextState);
});

Note for testing: confirm the mixed state announcement, and the two different resolutions of pressing "Mute all" (mixed/false both resolving to true, true resolving to false), with your standard browser and screen reader combinations before treating them as settled.
